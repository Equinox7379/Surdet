## 1. 完成后应当得到什么

Surdet 的产品定位：**以桌面创作为中心，让人类和外部 AI 使用同一套公开能力，制作有完整演出、独立视觉、分支与收藏、可维护且可交付的 2D Galgame。**

终态必须同时满足：

1. 从空白项目或已有模板开始，配置剧本、角色、场景、声音、界面、路线与结局，不修改引擎源码。
2. 既能做静态日式 ADV/NVL，也能做多层场景、分层/动态角色、复杂但可管理的演出与轻量剧情交互。
3. 人在 Editor 中修改的对象，AI 能读取和返修；AI 创建的项目，人能打开、看懂、继续编辑。公开接口、文件和 UI 不各有一套真相。
4. 长篇项目具备章节管理、引用定位、译稿/配音管理、真实预览、可追踪调试与明确恢复路径。
5. 默认 Player 可直接交付；自定义 UI、收藏与回想不需要复制另一套菜单、存档或解释器。
6. Windows 游戏包和桌面浏览器 Web 产物可以在没有 Surdet 源码/开发服务的环境中运行；多部作品的安装与存档身份隔离。
7. 正常失败能明确定位和恢复，已经运行稳定的项目不会因新增能力被自动换皮、改剧情、迁移未知数据或丢失进度。
8. 最终用实际制作、玩家操作、成品包与人/AI 接管证明以上结果，而不是用 API 数量、截图数量或通过测试的总数代替。

**这里的“无需再惦记 LetsGal”是以上生产能力的闭环完成，不是包含任意平台、任意玩法和任意云服务。** 下节的产品取舍要在总规划评审时明确接受，不能到收尾时临时删掉难项。

| R26 | 作者不靠开发者搭环境即可使用 | 部分/待核 | Windows 本地创作启动入口、可诊断依赖准备、无需源码仓库的作者交付；P10。 |
| R27 | 短提示词开始并交付可接手作品 | 部分、有样本 | 指南与产品入口同步、真实新上下文作者和人类接管；P11。 |

## 4. 所有阶段共同遵守的合同

### 4.1 一条实现链，不造第二套真相

```text
普通项目内容与配置
        ↓
Authoring：对象 / 读取 / 修改 / 校验 / 差异
    ↙                         ↘
Editor 人类编辑            CLI / MCP 外部 AI
    ↘                         ↙
        同一工作版本与预览
                ↓
Core → Renderer Runtime + Host / Player Shell
                ↓
      正常游戏 / Web / Windows 包
```

- 新增制作能力必须同时回答：读什么、改什么、引用谁、怎样验证、预览哪个版本、怎样保存与构建。
- Editor 只做交互适配，不能靠 DOM/Pixi 私有字段修改正式剧情事实；MCP 不维护另一份业务规则。
- Core 不引入文件系统、浏览器、第三方绘图/模型 SDK。动态模型留在 Renderer/资源层；Host 继续协调状态与输入。
- 复用普通文件格式；新增配置只为确有用途的角色、场景层、UI、语言等资源服务。不引入通用数据库、全仓对象 UUID 或插件管理平台。
- **新文档的首次写入口必须同批闭合版本范围。** 新角色/UI/语言等可编辑文档及其持久伴随元数据，要同时纳入既有快照与版本、对象/引用索引、指纹、差异、预览来源和真实构建依赖范围。需扩展 `isSnapshotPath`、工作存储/预览 overlay、对象指纹及相应消费者，不能让工作预览暗读来源的新配置，也不能另建影子版本系统。
- 每种新文档明确基线内容、工作内容及缺失/删除语义；即使只能 direct 修改，其作为候选的只读依赖也须有可验证身份。文件进入草稿不等于相关引用/重放已经接通。

### 4.2 默认行为与数据兼容

- 现有静态项目、已接受的默认 UI、旧 `@show/@mov`、合法存档与既有公共调用方属于真实兼容范围。
- 字段省略保持旧行为；明确清空、关闭与未提供分开。新增功能不能导致旧人物变大、换站位、收藏语义改变或 UI 自动改色。
- Player 既有显式参数优先于项目对应配置，再到引擎默认；读取结果须可解释实际生效来源，模板不得新增覆盖项目配置的硬编码。
- 保存继续区分剧情快照、跨周目 Profile、设备偏好、编辑器草稿。不能把收藏、语言偏好或编辑器选中对象混进同一个状态桶。
- 如需改变保存结构，先在本文件阶段记录中锁定受支持旧版本与最小转换；只覆盖真实旧数据，未知版本明确拒绝，不静默丢字段。
- **格式兼容与作品内容兼容分开。** schema 不变不能证明 pc 仍指向同一段剧情；内容改版要同时处理当前保存点和每一层调用栈返回点。仅验证场景存在、hash 告警、pc 限幅或槽位还在，都不能证明升级续玩正确。
- P1 先确定定位与内容版本所需最小事实，P6 的翻译键不得代替玩家定位。P10 只对已声明且可验证的更新续接：位置/返回点语义未变或有确定映射时可继续；无法证明时，在改变当前运行状态和好档前明确拒绝，保留旧档，并给出保留原版本继续、使用已提供的迁移路径或明确新开周目的可执行说明。
- 不用模糊台词匹配或近似位置迁移，也不为本规划建立任意版本通用迁移平台。旧档没有的内容身份不能事后猜造；其实际受支持范围在 P1/P10 记录，不能把原有宽容读取升级成可靠性保证。
- 新的变换、图层、动态角色、UI 状态和音视频恢复分别通过既有快照/validate/restore 路径；主要状态替换前完成可检查的失败条件。
- 不要求序列帧、物理模拟、声音解码逐样本一致；必须明确哪些恢复到语义位置、哪些恢复到时间点，以及不可精确恢复时的公开规则，不能假称完全一致。

### 4.3 Agent 权限、候选与引用

- `observe/stage/apply`、direct/candidate/integration 和来源写权限继续分开；普通返修不自动取得 apply。
- **本规划新增加的配置型操作**（新角色/图层文档、UI 文档、语言目录、收藏配置、项目扩展声明、发行设置）明确仅支持 direct。candidate/integration 必须在修改前拒绝；这一限定不撤销既有 `character.ensure`、变量或 CG 等已支持的候选操作，也不把所有角色相关写入一概禁用。
- P1 新增的 `scene.rename` 同时变更文件身份、跨场景目标与配置，限定 direct，与既有标签改名/场景删除保持一致；不以新入口解锁缺少组合事实的跨文件候选重构，也不撤回原候选操作。
- P1 `scene.move` 仅整理既有章节目录，不改场景身份/正文/路由；可能伴随固定原隐式入口，故同样限定 direct。目录整理不是新剧情顺序或第二套章节数据库，新增目标路径与旧路径删除仍由原工作稿/预览/提交事务负责。
- **既有场景/时间轴操作增加的新参数与引用**要完整进入现有候选依赖、产物、冲突、封装与重放。候选可以引用基线已存在且已解析的新配置；未支持的配置变更不能夹带进候选。
- 候选引用基线新配置时，记录操作时点的对象身份与所需指纹/依赖；比较、封装、重放和预览都能识别其变化，不能只检查某个字符串 key 存在。新增对象类型接入既有组合事实和 `working-object-fingerprint`，不是只加目录显示。
- **引用和伴随写入分开处理。** 普通候选正文修改若只使译稿过期，默认从源文/译稿版本计算只读失配提示，不暗写 direct-only 映射；若某个新组合操作必须同时改映射/其他配置才能成立，则在修改前明确拒绝该组合情形，该 change 的业务操作记录、revision、工作内容与来源文件保持不变；必要失败回执/调用日志仍按既有合同保留，不把“未应用内容”写成“抹掉失败记录”。不能漏掉必需写入后声称完整，也不能静默改成 direct。确需候选伴随写入时，先明确修订范围，再完整接入产物、冲突与重放。
- 如后续需要扩大配置候选支持，必须明确修订本条并完成全部受影响对象事实；不能只解锁入口。现有候选功能不得回退。
- 素材发布继续是独立授权的来源写入；未封存/已封存恢复身份、operationId、未知文件保护沿用现有规则，不用剧情 change 冒充素材事务。
- 重命名/移动/删除按真实结构引用处理，覆盖场景、选择项、call/jump 标签、时间轴、配置、UI、译稿和打包依赖；不得全文替换。
- 每个新写入口都有公开当前值、缺省状态、指纹、working/project 来源与分页版本合同；旧指纹拒绝、不产生半条操作记录。

### 4.4 视觉、交互和安全

- 默认视觉延续清爽细腻的现代日式 VN；动态只是表达工具，不用闪光、呼吸、景深等默认叠满画面。
- 自定义 UI 的样式可变，存读档、输入焦点、返回栈、回退和暂停语义仍由公共层负责；不让作品重新写一套播放器。
- 声明式内容配置不执行任意 JavaScript；显式启用的项目代码属于**受信任代码**，不是被证明隔离的不可信插件。窄参数接口、try/catch 和禁用回调只提供协作/故障边界，不证明代码无法访问同环境全局对象、联网或产生其他副作用。
- 项目代码启用前明确来源、依赖、构建期脚本以及浏览器/桌面执行环境的实际能力；不从网页/模型回复自动下载执行，不新增默认 Node/文件/Electron 特权桥。构建工具已有的宿主权限也应如实说明，不能宣称传入接口少就没有这些权限。不作“恶意扩展绝不能联网/访问数据”的承诺；若将来确需该目标，另选并验证实际隔离机制，本规划不预建通用沙箱。
- SDK/模型/字体/声音的许可与实际用途要在引入时核对；不从 LetsGal 安装包提取授权资源。依赖只按当前交付需要增加，不顺便升级工具链。
- 音频**制作**仍冻结；本规划的声音功能指使用和编排获准已有文件。生成、替换、混音加工或批量归一化真实作品声音须另行授权。

## 5. 实施路线与依赖

这是连续多阶段工程，不承诺一次对话完成，也不为每个小接口再申请一次开工。总规划获准施工后，按阶段保存可恢复成果；跨越下节列明的授权边界才暂停相关动作。

| 阶段 | 完整交付单元 | 依赖 | 规模判断 |
| --- | --- | --- | --- |
| P0 | 基线、终态与外部前提冻结 | 规划通过并获准开工 | 小 |
| P1 | 长篇剧本与项目制作入口 | P0 | 中 |
| P2 | 完整素材与角色资料链 | P1 的对象/引用约定 | 大 |
| P3 | 角色舞台、多层场景与演出编排 | P2 | 大 |
| P4 | 分层/序列帧、Live2D、Spine | P2/P3；模型与许可 | 大，外部前提敏感 |
| P5 | 作品主题与可视化 UI 制作 | P2/P3 | 大 |
| P6 | 多语言、配音管理与阅读表现 | P1/P2；与 P5 汇合 | 大 |
| P7 | 收藏回想、剧情资料与轻交互 | P1/P5/P6 | 中到大 |
| P8 | 真实调试、历史恢复与长项目运行 | 前面各项随实现接入，最后集中补缺 | 大 |
| P9 | 项目级受控扩展与既有玩法接线 | P5/P7/P8 | 中到大 |
| P10 | 本地创作交付、Windows/Web 成品链 | P1—P9 的必要运行依赖 | 大 |
| P11 | 完整制作与独立接管终验 | 所有 R 项实现、外部前提落实 | 中 |

推荐执行顺序为 P0→P1→P2→P3→P4→P5→P6→P7→P8→P9→P10→P11。若 P4 仅因许可/模型阻塞，可继续不依赖它的 P5—P9；P10 可以先验证静态项目，但不能以此替代动态模型打包或宣布总完工。

阶段状态须区分以下三个事实，仍记在第 11 节，不另建台账：

| 前置合同 | 何时确定/先交付什么 | 后续闭合责任 |
| --- | --- | --- |
| 独立项目布局与依赖方向 | P1 确定项目不位于引擎安装目录也能定位所需 Runtime；完成最小静态独立构建检查 | P2—P9 不新增开发仓库相对路径依赖；P10 验证作者发行版、全部资源与安装，不被早期静态检查替代。 |
| 文档版本/引用范围 | P1 冻结 4.1/4.3 的接入规则；P2 交付当期媒体和资源组 | P4 模型、P5 UI、P6 语言资源各自在首次引入时回接 P2 并补相邻验证。“当前类型可用”不是“未来类型全部完成”。 |
| 文本映射与 UI 数据绑定 | P1 确定身份/所有权的最小规则；P5 与 P6 开始前对齐文本键及绑定约定 | P6 完成译稿操作；P5 消费同一键，不先固化另一套语言表。 |
| 内容升级兼容 | P1 区分四类身份并确定必要版本事实；P6 保持各身份职责 | P10 验证真实更新后的当前位置和调用栈，不能等安装验证才首次设计续玩语义。 |

“合同已定”“当前类型已实现”“后续消费者已闭合”分别记录；某个前置阶段可以先交付其当前范围，但 R 项只能在全部必要消费者闭合后完成。

每阶段内部按“最小真实端到端 → 必要边界 → 普通提交/推送 → 阶段记录”推进。主代理不为阶段编号平均拆提交，不因总计划很大就提前建立所有接口和空目录。

## 6. 分阶段执行内容

### P0：冻结终态、基线与前提

**目标：** 后续压缩上下文或换执行会话时，范围、权限和已有成果不漂移。

- 核对当前 HEAD 与本规划基线的差异，保留别人的修改；只检查影响本计划的新增事实，不重跑旧全仓审计。
- 在第 11 节记录云端裁决、Owner 开工原话/范围、当前实现起点与新增的实质限制。
- 提前按第 7.1 节的五种交付物确认 Live2D/Spine 的主体、SDK/模型、可携带文件、通知和接收方许可前提，特别核对 Surdet Editor 的产品归类及下游作者；不把开发机能验证当作工具可发行。需向权利方确认时先由 Owner 授权联系，不自行接受协议、付费或发送申请。
- 固定验证环境：Windows 本机、桌面 Chromium Web、项目设计画布与目标内容规模。原生目录选择器/真实中文 IME 仍为 Owner 暂缓，若后续目标必须宣称这些路径完整，先取得恢复验证授权。
- 阶段涉及复杂新格式时，施工前在**对应阶段记录**补齐最少字段/错误/默认值与兼容决策；不得把本总规划替换成无穷的规格书审批链。

**完成证据：** 当前基线、外部前提和任务状态可由一个续接者确定。P0 不增加生产功能、不另造检查器。

### P1：长篇剧本与项目制作入口（R01—R04、R20—R21）

**作者结果：** 建立空白或示例项目，组织章节与复用段落，导入/返修正文，查看分支，可靠地继续编辑。

- 复用 `surdet new`、项目打开、脚本工作台、流程图和现有 history。先逐项确认已有能力，达标项只补缺失的接线/说明，不重写 UI。
- 在这里先确定独立项目布局：项目内容不依赖位于源码仓库 `games/`，共享 Player/Runtime 经明确的包或分发入口定位，依赖版本可解释；不把现有跨目录 import 固化进新模型/UI/译稿格式。提供最小静态项目的独立构建与正常启动检查，不复制 Player 源码作绕路，不把作者发行版/动态 SDK 包也提前扩进本阶段。
- 补齐场景/标签创建、重命名、删除、章节目录整理及引用感知修改；改变显示顺序不暗改剧情跳转。
- 正文与可视化字段操作往返保留注释、Unicode、未知但合法内容；批量搜索/替换先展示范围和差异，可撤销，不把整文件重排当作一次小改。
- 支持 UTF-8 纯文本和 CSV 剧本导入：字段映射、角色识别建议、歧义/坏行提示、导入预览。确认后进入普通草稿；不直接覆盖同名正式场景，不把任意文本默认为可执行指令。
- 复用场景/标签/call 表达公共片段，不新增第二种剧情执行语言。流程图可定位条件与调用方，连接编辑写回同一语义。
- 冻结“命名段落 + 台词映射”的最小所有权规则：译稿映射由正式内容操作维护，源文版本用于计算失配，候选伴随写入遵守 4.3；P6 再落实完整字段和工作面。不在所有文本行强塞永久 ID。
- 明确四类身份：创作对象引用用于当前修订的精确修改；翻译键用于跨语言文本对应；玩家保存点用于恢复执行位置；调用栈返回点用于恢复 call/return。可以建立显式关联，但不能拿其中一个字段直接保证其余三种语义。

**落点：** Editor `v4/script-workbench.ts`、`v4/script-source.ts`、`panels/flow.ts`、`history.ts`；Authoring `scene-document.ts`、`operations.ts`、`object-index.ts`、共享引用分析；CLI `new.ts` 和对应 authority。

**完成检查：** 中文/引号/条件箭头/call 标签真实往返；导入失败不改来源；跨场景修改的差异准确；保存重开、撤销重做和 AI 同稿返修保持身份；既有候选引用 R1 不回归；独立目录的最小静态项目不借原开发服务即可构建/运行，明确声明的合法 Runtime 依赖除外。

### P2：素材全链路与角色资料（R04—R05、R11）

**作者结果：** 准备好的图片、声音、视频、字体和后续模型进入项目后，能被发现、正确使用、整理并完整交付。

- 复用已有素材中心、来源授权、导入 authority、引用整理与恢复记录，扩展实际支持的资源类别；不要创建第二个上传/锁/恢复系统。
- 首批媒体范围：既有图片格式、WAV/OGG/MP3 声音、目标运行环境实测可解码的 MP4/WebM、TTF/OTF/WOFF2 字体。扩展名不是解码保证，失败应给出文件与原因，不偷偷转码或替换原件。
- 字体保留许可证文件；可记录素材来源/授权说明，但不制作自动法律认证系统。作品作者对授权负责。
- 建立角色资料的服装/表情/头像与默认显示名管理；对既有 `角色_服装_表情` 文件自动发现保持兼容，有配置时明确优先级和冲突提示。
- 素材预览、用法示例、实际引用位置、缺失/重名/未使用提示进入同一公开目录。未使用不等于可删除；清理必须给出精确目标和可恢复方式，由授权者决定。
- 安全替换/移动/改名覆盖真实消费者，包括 UI、时间轴、翻译专属资源和模型内部依赖；图片/模型引用完整性失败不得半写项目。
- 新增类别进入 project/working 读取、预览解析与构建收集；直接展示实际格式能力，不把已列目录但未支持的文件标成可用。
- P2 首次交付只关闭当期媒体/资源组及已存在消费者；P4/P5/P6 引入模型/UI/语言资源时，由引入阶段负责按 4.1/4.3 回接完整范围。新配置的工作预览必须读尚未写回的版本，不能回退成来源文件；资料依赖与实际媒体文件分别按各自既有存储合同处理。

**落点：** Authoring `asset-catalog.ts`/`asset-intelligence.ts`/`asset-relocation.ts`、CLI `asset-import-authority/`、Agent 图片导入服务、Editor `panels/asset-center.ts`/`asset-import-workbench.ts`、Renderer `services/render-asset-registry.ts`。

**完成检查：** 实际来源授权→导入→公开读取→编排→预览→获准写回；重复请求和中断恢复；改名后引用更新；坏媒体可解释；中文/空格路径；当期新增类型在构建产物中可消费。后续新配置至少验证一次 candidate 引用基线配置并识别其变化、一次工作预览读未写回配置、一次禁止伴随写入时 change 业务记录/工作及来源内容不变而失败回执如实保留；既有 character.ensure 候选保持可用。对真实资产不执行破坏性试验。

### P3：角色舞台、多层场景与演出（R06—R08）

**作者结果：** 独立控制人物构图、层次和表演，编辑器里摆出的画面能变成真实可保存演出。

- 角色独立的位置、缩放、左右朝向、透明度与前后顺序；支持命名的近/中/远距离及位置方案，允许单次覆盖。相机变换不能被用来假装单角色缩放。
- 新坐标以项目设计画布为基准，画布缩放只影响显示；角色锚点、相机空间与 UI 空间分开。旧 `left/center/right` 和固定尺寸项目继续按旧默认解释，不静默转换所有剧本。
- 新方案提供明确的锚点和可见范围；换表情时保持角色站位与基准尺寸，不能因图片透明边缘不同任意跳动。角色特定校准可配置，不能每张图都要求改引擎。
- Editor 舞台拖动/缩放操作选中的是来源对象，预览临时操作不会自动落盘；确认应用后才写普通草稿，可撤销。播放中的临时运行状态不能冒充封存版本。
- 场景支持背景、可独立移动的环境层、前景遮挡及适度视差；切景规则明确保留/清除哪些对象，旧项目维持现状。
- 扩展现有时间轴轨道和关键帧；支持片段复用、时长/缓动/并行和阻塞边界。复用不是任意脚本执行；片段引用必须可校验、可打包。
- 场景指令与时间轴修改同一人物属性时，按时间顺序和明确覆盖规则生效；暂停、快进、回退、读档、重新播放后不得残留上一个动作的回调。

**落点：** Core `timeline.ts`、DSL 解析/编译；Renderer `types.ts`、`layers/world/world-layer.ts`、`timeline-player.ts`、`world-effects-controller.ts`、Runtime commands/queries/presentation；Editor 时间轴/预览工作面；Authoring 场景/时间轴操作与事实分析。

**完成检查：** 至少两角色不同大小/朝向/遮挡；背景相机与单角色移动分离；不同画布比例保持构图；指令与时间轴一致；编辑→草稿试玩→写回→存读档/回退→打包显示一致；旧静态项目画面不被改动。

### P4：分层、序列帧与动态模型（R09—R10）

**作者结果：** 角色可以使用完整图片、组合部位、帧动画或合法动态模型，普通剧情不必为每种类型重写。

- P4a：分层身体/服装/眼/嘴等部位，可定义互斥组合与默认部件；组合由明确配置决定，缺部件不能悄悄换成另一表情。提供简单眨眼/待机/说话状态，默认静态作品不开启动画。
- P4b：序列帧顺序、逐帧时长、循环与单次完成；支持图片组，不建设视频转帧或建模工具。
- P4c：Live2D。根据施工时官方 SDK 与本机 Renderer 兼容性选定一个明确支持版本，列出模型入口、纹理、动作、表情等必要依赖；用户合法提供 SDK/模型后验证完整链条。
- P4d：Spine。根据合法 Runtime、Pixi 接入和实际模型选定一个明确导出版本；不默认同时支持所有历史版本。骨骼、atlas、纹理一起校验与发布。
- Live2D/Spine **是本总规划的必交付功能，但受 SDK、模型和许可前提约束**。前提缺失时记录阻塞，其他阶段可继续；不能以“留了适配接口”或“已下载”记为完成。取消其中一种需 Owner 明确修订总目标。
- 两种 SDK 的集成、开源仓库分发和最终游戏发布许可分别核对；不代替 Owner 同意协议、付费，不从竞品包复制 Runtime。[Live2D 官方许可入口](https://www.live2d.com/en/sdk/license/)、[Spine Runtime 官方许可](https://en.esotericsoftware.com/spine-runtimes-license)
- 私人验证、可分发 Editor、可编辑项目和游戏成品的许可结论分别记录，按 7.1 执行。仅在项目外安装 SDK 不能自行证明 Editor 不涉及可扩展应用或下游许可；不将开发者持证视为所有作者已获许可。
- 动态运行库按项目实际使用启用；静态作品不必安装、授权或加载未使用格式。可选接入不免除适用许可，也不为此先升级整个图形依赖链。
- 统一角色显示/切换、变换、快进、暂停和资源所有权；每种模型加载失败给出明确诊断。不以静态占位图通过动态模型验收。
- 快照保存可稳定恢复的模型/动作/表情/播放位置；对不可精确序列化的物理内部状态明确确定的重新初始化规则。测试依据公开规则，不要求伪造逐像素物理重放。

**落点：** P2 资源链、P3 舞台公共契约、Renderer 动态资源实现、表现快照校验/恢复、Editor 角色资源预览、Authoring 新角色配置读写；SDK 隔离于 Core。

**完成检查：** 在依法获准、依赖明确的独立环境中，四类角色均能在正常 Player 与 Editor 中显示、换表情、保存/读回、退出释放并进入相应获准产物；Live2D 与 Spine 分别有合法实物模型证据，不能互相替代。关页/换场景后无悬挂动画；禁用动态偏好不改变剧情推进。许可仅支持私人验证时，不登记 Editor 或游戏已经具备对外交付资格，R10 保持未完全闭合。

### P5：作品主题与可视化 UI（R12、R14—R15）

**作者结果：** 既可沿用默认 UI，也可为作品做自己的标题、对白、存读档、设置、历史、鉴赏及剧情面板，不改引擎。

- P5a：公开主题、字体、字标、背景、对话框/按钮资源、透明度和布局配置；先贯通读取→窄修改→真实预览。缺省作品保持已接受外观。
- P5b：在现有 Editor 中增加作品 UI 设计工作面，支持选中、层级、定位/尺寸、锚点、对齐、复制、撤销、数据来源与动作编辑。不是重做整个 Editor。
- 第一套实际组件覆盖：容器、图片、文本、按钮、开关/滑条、输入框、滚动列表、页签，以及复用公共存档/历史/鉴赏逻辑的内容容器。按用途实现，不追求竞品组件数量或复制其模板。
- 标题/系统六槽保持现有来源与返回语义；对白、选项、阅读工具栏和 HUD 走相应表现层。自定义外观不复制保存、翻页、回想、输入门禁或选择状态机。
- UI 绑定仅使用类型化的剧情变量、设置、解锁/条目数据和许可动作；文本不解析任意 JS。打开/关闭、确认/取消、存读档等动作有明确返回与错误结果。
- 设计画布不执行有副作用动作；真实预览使用正常 Shell/Runtime，并明确这是测试数据与运行上下文。恢复默认仅影响指定项目草稿，不能删除用户的自定义资源。
- 支持可复用作品主题文件和本地 UI 片段；分享仅打包依赖，不能携带密钥、绝对路径或无关个人数据。主题导入不自动启用代码扩展。
- 键盘焦点、字号/换行、减少动态和长列表必须可用；布局自适应限定目标桌面视口，不许把缩小截图算作交互验证。

**落点：** Renderer `theme.ts`/`ui-views.ts`/各 Layer；Host `player-shell-controller.ts`/`player-shell-slots.ts`；共享 Player；Editor `v4/surfaces.ts` 等；Authoring 新项目 UI 文档操作与资源引用。不要把作品 UI 改成另一套任意网页引擎。

**完成检查：** 使用同一共享 Player 得到默认主题与一套明显不同的定制作品主题；真实点击开始/选项/设置/历史/存读档/返回；撤销保存重开、AI 精确改一个元素、人类接管；旧默认截图只在受影响处比较，不重新让 Owner 审一轮旧美术。

### P6：文本、多语言与声音制作链（R11—R13）

**作者结果：** 正文、UI、选项和配音可以成套翻译/返修，语言切换不改变剧情逻辑。

- 补齐作者可控的文本样式、停顿/显示节奏、Ruby 与 ADV/NVL 排版；已有实现复用。富文本需有明确可转义语法和完整文本导出，不引入任意 HTML。
- 译稿独立于流程指令；对需要翻译/配音的文本建立稳定映射，保存源文版本以显示待重译。不能用当前行号、当前中文全文或模糊相似度静默匹配新正文。
- 在本阶段冻结具体映射格式：优先复用显式命名段落与项目文本键；匿名文本的映射由受控操作维护，歧义时要求确认。外部改文导致对不齐时保留原译稿并提示，不自动配给下一句。
- 具体字段遵守 P1 已确定的所有权与四类身份职责；与 P5 在引入文本绑定前对齐，不把翻译键当作存档/调用栈的天然稳定定位。候选修改导致源译失配时按 4.3 只读提示或拒绝必需的禁止伴随写入；不能暗改映射。
- 支持 CSV 导出/回导翻译和配音清单，包含角色、上下文、文本键、语言、状态；导入先差异预览，缺行/重复键/变量占位符/Ruby 错误可定位。人工和外部 AI 使用同一流程。
- 正文、选项、人物显示名、项目自定义 UI 与词条均纳入语言目录；路径/变量名/场景标签不翻译。语言偏好独立于剧情存档，切换不重置路线。
- 配音绑定支持按文本键与语言关联已有文件，缺配音不阻塞阅读；自动模式与语音完成/快进/历史重播/切场景的关系明确。
- BGM、环境声、SE、语音、视频走已有独立通道与生命周期；音量、淡变、循环、暂停/恢复、菜单音乐不互相抢状态。素材实际无法解码要报告，不靠伪成功继续。
- 不内置翻译模型/TTS 服务；不生成真实作品音频，不因这一阶段解除音频生产冻结。

**落点：** Core 文本事件/插值/`localization.ts` 的职责边界；Renderer 文字布局、Ruby、`audio-manager.ts` 与 presentation；Authoring 文本/语言目录操作和校验；Editor 译稿/语音关联工作面；共享 Player、打包依赖。

**完成检查：** 同一片段中/日/英切换，选项逻辑相同；源文增删/重排后旧译稿不串句；字体缺字/长句可诊断；配音和历史重播不改变正文状态；刷新读档与语言偏好一致；使用获准已有声音文件即可完成技术验证。

### P7：跨周目收藏、回想与剧情资料（R16、R23）

**玩家结果：** 通关后能查看结局、收藏与资料，重温片段时不污染正常进度；作者能通过配置完成这些功能。

- 保留现有随存档解锁语义；新增项目显式选择的跨周目收藏策略，CG、音乐、文本回想、结局/词条分别配置。旧作品不自动改成永久解锁。
- Profile 保存累计解锁，普通存档保存当次剧情状态；读旧档/开始新周目不撤销永久收藏，编辑器试玩不写正式玩家 Profile。移除内容条目时保留可诊断的旧记录，不擅自清档。
- 增加结局册、人物档案/用语辞典、收集进度与防剧透显示；同一数据和模板可被默认 UI、定制 UI 和 AI 读取，不复制第二个图库。
- 回想必须有独立进入/退出合同：使用作者定义的入口与必要变量条件，禁止任意跳到一句台词就声称完整回放。
- 回想期间不写普通自动存档、不累计正式周目、不泄漏临时变量；离开后返回原菜单/正常剧情的正确位置。可复用现有保存/重置/恢复能力，但不能只依赖 `hostJump`。
- 简单选择面板、好感/物品 HUD 使用已有变量和规则；状态来源可见，不能把 UI 上的数字当作独立状态。

**落点：** Core 解锁/通关状态、Host `profile-store.ts`、共享 Player `galleryView`/通关记录、Renderer Gallery/SystemPanel、Authoring Gallery/资料配置、P5 绑定。

**完成检查：** 通关/读旧档/新游戏/重启后的收藏规则；两作品互不串收藏；从标题与剧情分别进入回想再退出；取消/失败无普通档污染；翻译词条正确；旧项目仍按旧策略运行。

### P8：真实调试、项目历史与规模能力（R17、R19、R22）

**作者结果：** 知道“当前在跑哪个版本、为什么到这里、画面来自哪里”，可以定位和恢复问题，长项目不会要求一次载入全部资源。

- 复用现有预览观察、因果轨迹、检查点与路径重放，补可用的断点、单步和变量/调用位置视图；断点与作者意图绑定，正文变更失配时提示而不是偷偷停到别句。
- 从当前位置开始必须明确初始状态：使用真实已记录路径或作者指定测试条件。不把临时测试变量写进来源，也不把有外部影响的动作当成无副作用跳转。
- “画面→对象→来源片段”与“修改→差异→同版本真实预览”打通角色、场景层、时间轴、UI、译稿；缩略图/离线轨迹不冒充正式试玩画面。
- 剧情覆盖报告区分未访问、条件未满足、测试预算耗尽、运行失败；不能用静态图遍历宣称所有状态组合都验证过。
- 历史恢复沿已有草稿、history、文件 authority 与 Git 能力；先显示选定版本与当前差异，遇到外部未知修改保留双方，不自动覆盖整项目。
- 明确“内容历史”与“包含素材的完整交接包”：不能因正文可恢复就暗示被删媒体也有备份。避免自建 Git、自动海量素材快照或无法解释的恢复副本轮换。
- 交接版本规则复用 P10：默认导出某个已保存版本，明确活动草稿未随包转移；如选择工作草稿则导出其可核对内容为新项目，不复制原目录的 change/候选/批准身份。不把移动文件夹当成跨根目录事务续接。
- 资源加载按真实依赖分批、可取消、可重试；错误显示具体文件，离开预览/回想/项目后释放相关实例。先测真实问题，再针对瓶颈处理，不搭后台队列/通用缓存平台。
- 提供作者主动导出的轻量运行诊断（位置、版本、错误和所需局部日志）；不默认采集全项目、隐私路径、密钥或上传云端。

**规模验收建议基线：** 200 场景、总计约 5 万条对白、可达分支和代表性媒体混合的技术夹具。只为测试生成普通文本，不创作一部新商业作品、不复制数百份大图。该规模是拟交付目标而非当前性能声明。

在 P0/P8 的阶段记录写明本机硬件、输入、初始测量与最终可接受阈值；至少检查编辑输入/搜索、切章、首次及再次预览、取消加载、连续进出场景的资源趋势。不能把日后任意调整门限当作“通过”，也不要求所有硬件达同一帧率。已有性能红灯是否受影响据实说明。

**落点：** Editor `preview*.ts`、`history.ts`、`project-io.ts`、配置草稿与项目 authority；Core 模拟/轨迹；Renderer `loading-progress.ts`/`resource-lifecycle.ts`/`frame-scheduler.ts`；CLI 预览观察服务。

**完成检查：** 新功能均能被调试器准确定位；恢复后保存重开一致；未写回/封存/来源身份不混淆；规模与资源数据来自实际运行；正常界面不塞满内部技术告警。

### P9：项目扩展与轻量玩法（R23—R24）

**作者结果：** 普通 Gal 用配置完成，确实超出内置能力时在项目内开发，不必 fork 引擎。

- 整理现有自定义指令、Host 系统、Renderer 插件和 Player UI 槽位，公开必要的组合方式；不把狭窄帧回调接口包装成“万能 SDK”。
- 项目扩展声明自己的指令/配置、UI 入口、可保存状态及释放钩子；版本与不支持的能力在加载/构建前可诊断。
- 扩展是显式启用的受信任项目代码。启用前说明代码/依赖来源、安装及构建期执行脚本、运行所在进程和环境能力；普通内容不能自动注册代码。浏览器环境仍可能有网络/站点存储等全局能力，构建进程具有其宿主权限；窄接口不构成隔离证明。桌面继续使用既有受限桥，不为扩展默认新增特权。捕获异常/停用插件不撤销已产生的副作用。
- 保存前校验扩展状态；缺扩展/版本不兼容/恢复失败时给出具体原因，不静默丢状态并让玩家继续覆盖好档。扩展卸载不删除用户项目数据。
- 既有规则的必交付范围限于下表八项。每项均要能由普通项目配置和既有指令使用，不能依赖示例角色/敌人硬编码；不增加多格阵型、战棋、实时战斗、技能树或装备制作系统。

- AI 能读取扩展声明、参数和校验结果；普通内容 Agent 不能借注册扩展绕过资产、文件、发布或网络权限。

## 8. 与风险相称的验证方法

### 8.1 每项功能完成到哪一层

| 层级 | 要证明什么 | 不能拿什么替代 |
| --- | --- | --- |
| 内容合同 | 合法/非法参数、引用、缺省和范围明确 | 只看类型编译或文档字段存在。 |
| Authoring/Agent | 公开读取→修改→重新读取、旧指纹拒绝、工作/来源隔离 | 主代理手工改 JSON 后的成功。 |

| 数据生命周期 | 保存/读取/回退/取消/重启/换项目符合合同 | 只比较某个内部对象且没看画面。 |
| 成品 | 独立运行、完整资源、无开发路径、作品身份隔离 | Vite 开发页或构建退出码。 |
