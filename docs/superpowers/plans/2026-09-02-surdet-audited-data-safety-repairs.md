# Surdet 已审计数据安全修复实施计划

日期：2026-09-02
状态：本地施工与复核完成，等待普通推送
范围：素材整理历史/取消边界、场景保存并发边界、场景改名自动保存恢复

## 目标

关闭独立审计确认的五个数据安全缺口，同时保持现有产品功能与界面行为：

1. 已完成的素材整理记录不因项目后续合法编辑而重新阻断启动、查询或绑定；当前内容变化只影响“能否撤销”。
2. 素材整理计划与取消在进程中断后仍有可重试的公开状态，不再产生新的无记录工作区，也不先宣称取消成功再清理。
3. 场景新建、改名和删除不覆盖或误删外部程序刚创建/替换的文件。
4. 场景改名涉及的新场景、引用改写和旧路径删除作为一个保存单元；自动保存恢复不得只恢复引用而丢失新目标。
5. 保留现有中文交互、场景目录、流程图、素材中心和 Agent 能力，不改变 `.gal` 语法与运行时语义。

## 约束与设计决定

- 不新增通用事务平台，不引入新依赖；优先复用现有项目身份、项目租约、写入协调器、Authoring 批量写入与恢复能力。
- 素材整理继续使用现有状态模型。计划先写外部 `PLANNED` 记录，再幂等物化项目工作区；取消先严格清理已知工作区，再写 `CANCELLED`。
- 已完成素材整理的历史校验只验证持久记录与不可变回执的自洽性；项目工作区中的硬链接副本会随合法后续编辑变化，不能冒充不可变历史。当前项目文件与实际撤销所需副本只在撤销前置检查中验证。
- 场景写入只接受 `content/scenario/**/*.gal` 的规范相对路径。计划阶段捕获当前身份，提交阶段重新核对；创建必须拒绝已存在目标，删除必须拒绝身份已变化的旧文件。
- 场景改名批次包含新场景、所有被改写引用场景及旧路径删除。失败时保留 dirty/待处理状态，不把部分结果报告为保存成功。
- 自动保存格式只做支持该批次恢复所需的最小扩展；恢复前先验证全部成员，再整组应用。旧格式出现缺失场景键时不再部分恢复。
- 不清理无法证明归属的历史无记录工作区；只阻止今后继续产生。未知文件、符号链接或身份不符均失败并保留现场。

## 完成标准

- 五项缺陷均有能在旧实现失败、在新实现通过的永久回归测试。
- 后续合法编辑不影响历史读取；撤销仍对当前变化失败关闭。
- 计划/取消崩溃窗口不再制造不可公开恢复的新状态。
- 场景目标外部创建不会被覆盖，旧文件外部替换不会被删除。
- 改名自动保存不会产生“引用已恢复但新场景不存在”的悬空状态。
- 相关测试、类型检查和构建通过，Luna 独立复核无未处理高风险问题。
- 本轮改动已普通提交并推送；无关未跟踪文件和受保护文件未被纳入提交。

## 本地完成记录

- 素材整理历史只校验持久记录自洽；当前项目变化仅在用户真正撤销时检查。连续 A→B→C 与整理后继续编辑均保持历史可读。
