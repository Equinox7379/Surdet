## 3. 行内文字标签（重点）

**对应：** R12 / P6。总规划 P6 写明“补齐作者可控的文本样式、停顿/显示节奏、Ruby 与 ADV/NVL 排版……富文本需有明确可转义语法和完整文本导出，不引入任意 HTML”。P6a—P6c 交付的是文本映射、多语言播放和已有配音关联（总规划 11.16—11.18，见归档原文），行内样式与节奏还没有实现：DSL 规范里正文只有 `{变量}` 插值和《》注音（`docs/dsl-spec.md:35`、`:76`）。

### 3.1 作者要能写出什么

```gal
凛：你说什么？<w=400>……<color=accent>再说一遍</color>。
沈岳：<size=0.8>其实，</size><w>我一直都知道。
门外传来<shake>咚、咚</shake>的敲门声。
凛：等一下，我还没——<nw>
沈岳：来不及了。
```

对应的效果：强调色、耳语变小、句中停顿、句中等点击、抖动字、被打断的台词直接接下一句。这些是日式 ADV 最常用的文字演出，目前只能拆成多句或放弃。

### 3.2 现状（已核实）

| 环节 | 现在怎么做 | 依据 |
| --- | --- | --- |
| 插值 | Core `interpolate()` 把 `{名}` 换成变量值；未声明的保持原文；`{{`/`}}` 转义；替换值原样插入 | `packages/core/src/runtime/interpreter.ts:1341` |
| 文本事件 | `value` = 先取译文或原文，再插值后的整串字符串；Renderer 直接消费 | `interpreter.ts:87`、`:277-282` |
| 注音 | 只在 Renderer 解析：《》前面整段都当基础字；`stripRuby` 供文字记录、NVL 使用 | `packages/renderer/src/ruby.ts:14`、`:45` |
| 打字机 | `Typewriter` 按 UTF-16 码元切原始字符串，标记字符也占打字时间；没有停顿、变速 | `packages/renderer/src/text-buffer.ts:10-93` |
| 每帧显示 | 控制器每帧把已打出的前缀交给对话层，对话层对前缀重新解析注音、重新换行 | `runtime/presentation-controller.ts:595-599`、`layers/dialogue/dialogue-layer.ts:1324` |
| 自动播放停留 | 按 `value.length` 计算，标记字符也算字数 | `presentation-controller.ts:623` |
| 文字记录、NVL | 都只存/显示 `stripRuby` 后的纯文本，NVL 不显示注音 | `presentation-controller.ts:879`、`:886` |
| 编辑器 | 正文和源码都是原生 `<textarea>`，没有语法高亮 | `packages/editor/src/v4/script-workbench.ts:367`、`:787` |
| 现有剧本 | 34 个受跟踪 `.gal` 的正文行里没有 `<`、`[`、`]`、`\`、`|`；`>` 只出现在选择肢箭头 `->`；`{}` 只用于插值 | 本轮 `git ls-files '*.gal'` 扫描 |

**现存缺陷（已核实，本轮实际运行 `parseRuby`）：** 中文书名号会被当成注音。`我在读《红楼梦》。` 被解析为基础字“我在读”加注音“红楼梦”：画面上“红楼梦”变成小字压在“我在读”上方，文字记录经 `stripRuby` 后只剩 `我在读。`，书名整个消失。受跟踪剧本还没用过《》，所以目前没人踩到；中文作品里书名号很常见，迟早会遇到。

### 3.3 语法：推荐尖括号标签

| 方案 | 写法 | 主要问题 |
| --- | --- | --- |
| **A 尖括号（推荐）** | `<color=accent>危险</color>`、`<w=500>` | 外观像 HTML，需要说明只是固定的小标签集；颜文字 `>_<` 等靠宽松规则按原文显示 |
| B 花括号（Ren'Py 式） | `{color=#f00}危险{/color}`、`{w}` | 与现有 `{变量}` 插值冲突：`{b}`、`{w}` 和名为 `b`、`w` 的变量无法区分，以后声明一个变量就会悄悄改变显示 |
| C 方括号（KAG/Tyrano 式） | `[color=#f00]危险[/color]`、`[l]` | 与选择肢条件 `[if:...]` 同形；中文正文也会写 `[注]` 之类 |

推荐 A：对现有内容零冲突；和 `{}` 插值、`[if:]` 条件、《》注音三种既有记号互不重叠；开闭成对，嵌套一眼可见；用过 Unity TextMeshPro、Naninovel 的作者也熟悉。它**不是 HTML**：只认登记过的标签名，每个标签最多一个取值，没有属性、脚本、图片或链接，符合 P6 “不引入任意 HTML”。

### 3.4 标签清单（分三批）

| 批次 | 标签 | 取值 | 作用 |
| --- | --- | --- | --- |
| 一 | `<b>…</b>` | — | 粗体 |
| 一 | `<i>…</i>` | — | 斜体（中文字体多为合成倾斜，效果一般，见 3.13） |
| 一 | `<color=…>…</color>` | `#RGB`、`#RRGGBB`，或主题色名 `text`、`textMuted`、`accent`、`accentSoft`、`danger` | 文字颜色；主题色名取自 `packages/core/src/theme-tokens.ts:3-17`，换作品主题时跟着变 |
| 一 | `<size=…>…</size>` | 倍率 0.5–2.0 | 相对正文字号；玩家调字号（第 4 节）时一起缩放，所以不提供绝对像素 |
| 一 | `<w=毫秒>` | 1–10000 | 打到这里停一会儿 |
| 一 | `<w>` | — | 打到这里等玩家点击，点击后继续本句 |
| 一 | `<speed=…>…</speed>` | 倍率 0.1–10 | 相对玩家设定的打字速度 |
| 二 | `<shake>…</shake>`、`<wave>…</wave>` | — | 逐字抖动、波浪；“减少动态”开启或快进时静止 |
| 二 | `<em>…</em>` | — | 着重号（每字一点），复用注音排版 |
| 二 | `<nw>` | — | 只能放在句末：本句打完不等点击，直接进入下一句 |
| 二 | `<ruby=读音>基础字</ruby>` | 读音 | 显式注音（见 3.6） |
| 三 | `<u>`、`<s>`、`<style=名>`、`<instant>` | — | 下划线、删除线、项目命名样式、整段瞬显。有真实作品需要时再开，不预先做 |

各位置支持范围：

| 位置 | 样式（b、i、color、size、em、ruby） | 效果（shake、wave） | 节奏（w、speed、nw） |
| --- | --- | --- | --- |
| ADV 正文 | 支持 | 支持 | 支持 |
| NVL 正文 | 支持（第二批） | 静止显示 | 忽略：NVL 整句一次出现 |
| 选择肢文案 | 支持 | 不支持（M005） | 不支持（M005） |
| 文字记录 | 支持（第二批；第一批先显示纯文本） | 静止显示 | 去掉 |
| 说话人位置 | 不支持（M005） | 不支持 | 不支持 |
| `@title`、`@chapter`、`@tip` 等指令参数，配置里的名称与词条 | 不解析，按原文显示 | — | — |

### 3.5 解析规则

```text
开标签  <名称> 或 <名称=值>
闭标签  </名称>
单标签  <w>、<w=值>、<nw>
名称    只限登记表里的小写 ASCII 名称
值      1–32 个字符，不含空白、尖括号、中英文冒号
转义    \< 输出 <；\\ 输出 \；其他反斜杠按原样显示
```

- 只有“`<` + 已登记名称 + 合法取值 + `>`”才是标签。`>_<`、`<3`、`a < b`、`<<标题>>` 都按原文显示，作者不用转义。
- 形似标签但名称未登记（例如 `<colr=red>`）：按原文显示，Lint 报 M001 警告并给出最接近的名称。
- 样式、效果、变速标签必须在同一句内闭合并严格嵌套；`<b><i>…</b></i>` 报 M003。
- 标签值里不能用变量（`<color={c}>` 报 M004）。动态样式等第三批的命名样式再考虑。
- 取值不允许冒号，保证“首个冒号前是说话人”的规则（`packages/core/src/dsl/lexer.ts:211`）不受影响。
- **解析器只有一份，放在 Core**：纯函数、不依赖 DOM。输出可见单元（字素簇、注音组）、样式区间、控制点（停顿、等待点击、变速、`nw`），以及每一段在源码中的位置（供 Lint 定位、Editor 高亮、术语定位）。Lint、Renderer、Authoring、Editor 都调用它，不各写一套正则。
- **运行时不因为标记出错而中断。** 源剧本中的错误在编译/Lint 阶段报出；运行时遇到坏标记按原文显示。译文中的坏标记在译稿校验时报错，运行时退回原文，沿用当前“缺译、过期或失配时回退原文”的规则（`docs/known-limitations.md` 作品多语言一节）。

新增诊断码族 `M`（行内标记）；现有码族为 L、S、C、J、V、T、TL、W（`docs/dsl-spec.md:244` 起），没有冲突。

| 码 | 级别 | 含义 |
| --- | --- | --- |
| M001 | 警告 | 形似标签但名称未登记，按原文显示 |
| M002 | 错误 | 样式、效果或变速标签没有闭合 |
| M003 | 错误 | 闭标签与最近的开标签不匹配，或没有对应的开标签 |
| M004 | 错误 | 取值缺失、超出范围、格式不对或含插值 |
| M005 | 错误 | 标签用在不支持的位置（说话人；选择肢里的节奏或效果） |
| M006 | 错误 | `<nw>` 不在句末 |
| M007 | 警告 | 疑似旧式注音写法（只在采用 3.6 方案乙时启用） |

### 3.6 与插值、注音、书名号的关系

1. **插值的值永远是普通文字。** `interpolate()` 替换时对值做转义，玩家输入的名字或变量内容不会变成标签或注音。顺序固定：取原文或译文 → 插值（值已转义）→ 交给共享解析器。文本事件的 `value` 仍是带标记的字符串，存档、回退快照和运行轨迹的字段格式不变（推断：现有消费方都以字符串保存 `value`，开工前由 GPT 确认没有遗漏的二次解析点）。
2. **注音与书名号（需要决定）。**
   - 方案甲，不改行为：保留 `基础字《注音》`，新增 `\《` 转义。零迁移，但每个书名都得记得转义，忘了就出现 3.2 的缺陷。
   - **方案乙（推荐）：** 不带标记的《》一律按书名号原样显示；注音写成 `｜基础字《注音》`（全角或半角竖线标出基础字起点，日文网络小说的通行写法）或 `<ruby=读音>基础字</ruby>`。受跟踪内容没有用过《》，迁移成本为零；外部项目如果用过旧写法，Lint 以 M007 提示（《》里全是假名或拉丁字母且很短时），不自动改写。
   - 这是公开 DSL 行为的变化。按 AGENTS“已发布公共接口需由任务书明确兼容范围”，请 Owner/GPT 决定；建议采用方案乙，兼容范围只做 M007 提示。
3. `{{`、`}}` 的插值转义保持不变。

### 3.7 播放语义

打字机改为按“可见单元”推进：字素簇用 `Intl.Segmenter` 切分（与 `packages/renderer/src/text-wrap.ts:27` 一致），注音组整组出现，标签本身不占时间。

| 情况 | 规则 |
| --- | --- |
| 正常打字 | 每个单元耗时 = 1000 ÷（玩家速度 × 当前 `<speed>` 倍率）毫秒 |
| `<w=毫秒>` | 打到此处停指定时长；打开菜单期间不计时，沿用现有暂停补偿 |
| `<w>` | 打到此处停住并显示继续提示；点击或回车后继续本句，不进入下一句，也不打断语音 |
| 打字中点击 | 立即显示到下一个 `<w>`，没有就到句末；途中的 `<w=毫秒>` 一并跳过 |
| 快进 | 忽略所有停顿和 `<w>`，和现在一样整句瞬显 |
| 自动播放 | `<w=毫秒>` 照常停；`<w>` 视为一次自动停留（基础停留 + 每字停留 × 上一段可见字数）；句末停留改按**可见字数**计算，顺带修正 `presentation-controller.ts:623` 现在按原始长度计算的问题 |
| `<nw>` | 本句打完立即进入下一句，不等点击、不等语音；快进和自动播放下行为相同 |
| 口型 | 停顿和 `<w>` 期间“说话中”置为否，继续打字时恢复（现有 `setPortraitSpeaking`） |
| 语音 | 不受停顿影响；`<w>` 不停止语音 |
| 切换语言 | 沿用 `replaceText` 的比例进度（`text-buffer.ts:52`），改按可见单元换算；停顿状态清零 |
| 存读档、回退 | 仍从句首重新播放（现有规则），存档格式不变 |
| 已读与“快进遇未读即停” | 仍按整句判断，不变 |

### 3.8 排版与渲染

- 把 `layoutRuby`（`packages/renderer/src/ruby-layout.ts:22`）扩展为通用的富文本排版：输入可见单元和样式区间，按样式测量宽度，继续使用 `wrapCjkMeasure` 的中文避头尾规则；每行行高取该行最大字号；注音组和着重号是不可拆的单元。
- **整句先排版，再逐字揭示。** 现在每帧都对已打出的前缀重新换行（`dialogue-layer.ts:1324-1333`）。改为句子出现时排一次版，打字只控制显示到第几个单元（推断：能消除避头尾处的字在打字过程中跳到下一行的现象，开工时用实际长句验证）。
- 绘制：同一行、同一样式的一段用一个 Pixi `Text`，沿用现有注音对象池；效果段逐字一个对象，由现有渲染时钟驱动，暂停时冻结，“减少动态”或快进时静止。没有标记的句子保留现在的单个 `Text` 快速路径。
- 主题色名走现有主题投影绑定，换主题时颜色跟着变。
- 现有溢出诊断（`TEXT_SCROLL` 等，`dialogue-layer.ts:447-458`）改用富文本排版得出的实际高度。
- 第二批让 NVL 和文字记录使用同一排版，不再只显示纯文本；NVL“去掉重复的当前行”的比较（`presentation-controller.ts:103-113`）改用共享的纯文本函数。

### 3.10 Editor 交互（Claude 负责）

- **剧本正文行：** 没聚焦时按标签渲染（颜色、粗细、字号直接显示；`<w=…>` 显示成小号“停 0.4 秒”记号，`<w>` 显示成“▸”，效果段加细虚线和小字说明）；聚焦时回到原生 textarea 编辑原文，背后叠一层同字体的高亮镜像（标签变淡、取值着色）。输入法、撤销和选区仍是浏览器原生行为。
- **补全：** 输入 `<` 弹出标签列表（来自 Core 登记表，每项一句说明）；`<color=` 列出主题色名和最近用过的颜色。
- **选中包裹：** 选中文字后出现小工具条（粗体、颜色、字号、停顿、抖动）；快捷键开工时核对现有绑定后再定。
- **问题面板：** 显示 M 类诊断，提供“补上闭合标签”“把 < 转义”等一键修复。
- **源码视图：** 同样加高亮镜像（第二批）。
- **译稿页：** 原文、译文里的标签显示成小标签块；两边标签对不上时给出提示。
- **统计与搜索：** 默认按可见文字计数和匹配；搜索可切换为“包括标记”。
- **预览：** 就是真实 Player，不在编辑器里另做一套文字效果。
- 原生中文输入法实机验证仍按 G3 由 Owner 暂缓；Editor 自动化测试不代签输入法体验。

### 3.12 验收

- **解析器单元测试：** 转义、嵌套、未闭合、错位闭合、未知名称、越界取值；`>_<`、`<3`、`a < b`；插值值里含 `<` 和《》；字素簇（emoji、组合字符）；两种注音写法；书名号。
- **真实 Player**（用 Starter 的夹具副本，不改正式作品）：一句同时含颜色、字号、`<w=500>` 和 `<w>`——停顿时长在容差内；打字中点击只显示到 `<w>`；第二次点击继续本句；第三次进入下一句。另测快进忽略停顿、自动播放、语音不被打断、在 `<w>` 处存档后读档从句首开始、回退、切换语言（译文带标签）、文字记录、NVL、选择肢颜色、“减少动态”下抖动静止、`size=2` 长句的溢出诊断。
- **Editor：** 真实输入 `<` 出补全、选中包裹、问题面板定位与修复、保存后重开；译稿 CSV 导出再导入时标记原样往返。
- **Agent：** `capabilities.describe` 能看到标签表；CLI lint 返回带行列的 M 类诊断；Agent 用既有写入操作写入带标签台词，并能在预览里看到效果。
- **风险等级：** Core 与 Renderer 部分属于 AGENTS 的 C 级（公共接口、跨层），按 C 级验证；Editor 部分按 B 到 C 级。

## 11. 开源前配套

**对应：** 台账决策 9（先完成独立桌面前端，再正式开源）与总规划 11.39。

**现状（已核实）：** MIT 已获 Owner 确认，各引擎包附许可副本；仓库保持 PRIVATE，没有发布 npm 包或安装包；README 有短英文介绍；`docs/README.md` 是面向开发与 Agent 的索引，`docs/dsl-spec.md` 是规范而不是教程；新项目模板有空白和示例两种，自带 Agent 指南与 MCP 示例（台账“PR #2 新项目 Agent 上手材料”）。11.39 列出的公开前剩余决策（示例作品与素材权利、公开历史方式、Actions 日志）仍未定。

**目标：** 一个没读过源码的作者，能只靠随附文档完成“安装 Editor → 新建项目 → 写剧本（含行内标签）→ 试玩 → 导出 Windows 游戏”。

**方案：**

1. **作者指南**：在仓库内新建面向作者的中文指南（建议 `docs/guide/`），按真实操作顺序写，截图取自真实 Editor。与 `dsl-spec.md` 分工：指南讲怎么做，规范讲精确语法；指南只链接规范，不复制第二份语法表。
2. **一篇完整教程**：用空白模板从零做一个两条分支、一个结局的短篇，覆盖本规划新增的行内标签、阅读设置和导出。教程项目只用可以公开的素材，或使用占位色块。
3. **版本与兼容说明**：写明 DSL、项目文件、存档 schema 各自的版本号在哪里、哪些旧版本受支持、不支持时如何报错。这是给作者的承诺，内容由 GPT 按现有 `migrate.ts` 等实际实现核对，不凭空承诺。
4. **站点**：先不引入文档站框架。等 Owner 决定公开方式后，再看是否用 GitHub Pages 之类直接渲染 `docs/guide/`（AGENTS“不为假设中的未来需求制造间接层”）。
5. **公开动作**：转公开仓库、npm 发布、安装包发布都是 D 级动作，分别取得 Owner 授权；本节只做准备。

**分工：** Claude 写作者指南和教程（以前端操作流程为主）；GPT 核对技术准确性，维护 DSL 规范、能力矩阵与兼容说明。

**验收：** 由一个新的上下文（或 Owner 指定的人）只读指南完成上面的完整流程，记录卡住的地方并据此修改；不以“文档页数”作为完成标准。
