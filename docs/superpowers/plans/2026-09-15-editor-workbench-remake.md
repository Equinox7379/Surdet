## 已实现

- 正式 `index.html` 使用紧凑工具栏、统一工作区导航、灰白工作底色与低饱和强调色。未打开项目时提供原项目与审阅入口；九个模式保留。没有改用独立示例的存储或编译逻辑。
- 剧本目录、正文、画面与属性构成 A 三栏。两处分隔条可拖动或用方向键调整，双击恢复；重新挂载时清理监听。对白直接写入原场景文档，原撤销/重做、源码与稿件视图、导出入口保留。
- `Ctrl+K` 搜索当前项目场景、正文、时间轴与工作区，结果跳转复用原导航。正文结果持有原项目对象及内容，内容改变后拒绝旧定位；弹窗内的输入不触发项目撤销或保存，关闭按钮的 Enter 正常关闭。
- 当前对白显示可确定的背景/立绘来源，跳回原指令；条件或时间轴等动态边界仍明确停止静态推断。时间轴摘要读取原文档及共享校验、动作名称，点击节点直接打开原时间轴编辑器的对应节点；不新增时间轴业务状态。
- 素材列表、配置、时间轴、预览及审阅沿用既有工作面和真实动作，共享新色彩与字体层级。未改 Core、Authoring、CLI 或 Renderer 的业务实现，没有移除 Agent、隔离变更、候选、批准、写回能力。
- 实测发现关闭预览时，尚在等待源码指纹的加载可能继续启动并查询已销毁 Renderer。`preview.ts` 现在使关闭会话及其轨迹立即失效，并在异步步骤后停止旧加载；原解释器与运行器继续复用。

## 失败记录及处理边界

- 原全应用脚本直接填入已折叠的旧查找框，首次超时；改为通过原 `Ctrl+F` 展开再操作。时间轴节点断言曾误写“屏幕”，已改为共享真实名称“画面效果”。
- 长项目名在窄窗口溢出，已给项目上下文子项完整宽度约束。其间两次针对构建产物的复验未重新构建，仍命中旧 CSS；新鲜构建后通过，不把旧产物结果当成修复失效或成功。
- 保存回归初次遇到 `HUMAN_WORKSPACE_STATE_CORRUPT`，定向诊断确认是测试关闭前一浏览器上下文时异步撤销请求可能被中止，旧会话进入服务规定的 grace 保护，并非新 UI 修改了保存合同。测试现在等待真实 HTTP snapshot 确认仅剩一个活动会话、无 grace 会话，再验证单 Editor 保存；没有删除状态、假报 clean、自动重试实际写入或改服务门限。临时服务端诊断已移除。
- 后续连续切换曾实际捕获三条已销毁 Renderer 的轨迹查询错误，前述关闭失效修复及确定性反例覆盖此因；修复后真实磁盘回归无浏览器错误。
