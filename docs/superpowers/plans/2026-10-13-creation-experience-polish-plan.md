## 0. 交付目标与续接入口

这一轮不再追求“功能清单比对方长”，而是让作者能持续制作一部有统一界面风格、演出可以复用、规模增长后仍可用的 Gal。

最终应让作者做到三件事：

1. 不改引擎源码，就能配置一套有明确排版、层次和交互反馈的游戏界面，并在另一部作品里复用。
2. 常用站位和演出不用逐句重写；同一片段能绑定到不同人物，修改影响可看清，也能只改某一次使用。
3. 长篇作品的启动、章节切换和读档有真实耗时记录；只优化已定位的成本，不以加载失败、卡顿转移或恢复错误换取启动数字好看。

## 2. 范围与不变规则

### 纳入

- 作品自定义 UI 的细排版、背景/边框、状态样式和有界进出场表现。
- 复用现有主题/界面片段共享、舞台布局和时间轴引用，补齐其真实作者工作流。
- 当前规模与长篇负载的启动诊断；必要时改造场景加载，保留同一运行与恢复语义。
- 与上述内容对应的公开读取/修改、依赖检查、编辑器草稿、导出、作者文档及 Windows 验收。

### 不纳入

- 不把 `.gal` 换成 JSON 块，不给每一行塞永久 ID，不把全部参数改成字符串。
- 不新增通用样式语言、规则引擎、任意脚本样式、自动生成全配置表单或第二套播放器。
- 不新增模型聊天、云工坊、市场、在线资源服务、热补丁、签名/加密平台或跨平台矩阵。
- 不因本规划开放插件更高权限、修改预览安全配置或解除插件正式观察/续接限制。
- 不增加 Live2D、Spine、第三批标签、安装器或公开发行；这些仍不属于本轮。
- 角色属性模板、头像裁剪、任意参数“值/变量”双模式属于另行确认的需求，不因参考报告提到就全部加入。

### 保持的合同

- Windows 是唯一新增验收平台。Claude 的 Linux 结果与本机 Windows 结果分别记录。
- 存读档、回退、暂停、输入所有权、文字可读性、资源释放优先于动画好看；视觉层不得另造运行事实。
- 既有明确禁止存档/回退的阻塞阶段仍按原合同拒绝，不为展示新效果而擅自开放，也不把这种拒绝计作恢复缺陷。
- 保留作者已有默认行为。新增可选数据由当前解析器直接处理，不建立旧新格式转换、双版本加载或别名兼容层；若真的需要破坏已支持数据/接口，明确提出具体冲突再由 Owner 决定。
- 不新增/执行专项哈希校验，不用另一种“指纹”改名绕过。既有创作事务只通过原接口消费，不另发明摘要或验收设施。
- 正常功能安全不因恢复开源而削弱。既有素材包装也不在本轮擅自拆除。

## 5. U1：作品级界面的细排版与装饰

### 作者结果

对白、选项、存档列表和菜单能形成同一套视觉语言；作者在已有设计器里改数据即可生效，不需要修改 `src/main.ts` 或引擎 CSS。

### GPT：数据与公共链路

沿 `ProjectUiNode` 增加有限、有类型的可选字段。下列为规划语义，具体字段名由首个后端 PR 一次定稿，不在前端另造同义字段：

| 类别 | 拟支持的语义 | 必须明确的边界 |
| --- | --- | --- |
| 文字 | 字重、行高倍率、字距、文字阴影列表 | 使用既有字体角色；倍率/设计像素单位明确；有限数值，缺省保持现有表现，不执行任意 CSS |
| 背景 | 纯色、项目图片及有限线性渐变 | 背景图片用真实素材引用，适配方式有限枚举；渐变起止色和角度，不接字符串脚本或远程 URL |
| 框体 | 边框、圆角、内边距、装饰阴影 | 布局框和内容框分开；可见区域、滚动、命中区使用同一几何事实 |
| 皮肤 | 图片九宫格切片及中心填充 | 切片为原图像素，不能超过图片边界；小尺寸不能反转边角；复用现有素材目录与导出路径 |

- 生效顺序：先按原合同解析显式 `PlayerProject` 主题参数、作品主题及默认值，再应用控件明确值；玩家文字倍率在作者字号基础上生效，“减少动态”等阅读偏好仍优先于视觉效果。不得借新样式反转既有显式参数优先级。
- 缺省是继承当前行为；明确清空只清该项。不能用真假值判断把 `0`、透明背景或清空误当未提供；每种字段的清空表达在合同中唯一规定。
- 扩展当前 `readProjectUi`、`projectUiAssetKeys`、`validateUiAssets` 与既有 UI 修改入口，公开读取必须能拿到当前值和有效缺省；未知字段、非法引用、坏数值在修改前拒绝，不写半份配置。
- UI 修改沿目前 direct-only 范围，candidate/integration 在落盘前拒绝；不顺手开放组合写 UI。已有候选的依赖读取若受新资源影响，必须完整记录实际依赖，不能因 direct-only 漏掉引用。
- 图片移动/改名、主题共享、字体角色、自定义记录、译稿文本和 Windows 导出消费新字段；不要只完成设计器显示。

**主要入口：** `packages/core/src/project-ui.ts`、`project-theme.ts`、`theme-tokens.ts`；`packages/authoring/src/ui-operations.ts`、素材依赖与改名的实际调用方；`examples/shared/player/player.ts`。

### Claude：设计与可见实现

- 在原界面设计器中按“文字、背景、框体”分组，只展示当前控件适用的属性，中文标签及可理解单位，不堆通用 JSON 表单。
- 先为一套完整作品界面给出设计示例，由 Owner 确认视觉方向后再应用到默认作品外观；数据接口开发不必等待审美选择。不得借此重做 Editor 外壳。
- 可见实现以 `packages/renderer/src/project-ui-dom.ts`、`packages/editor/src/ui-designer.ts`、`ui-preview.ts`、`ui-player-preview.ts` 及相关表单为入口；若代码已在审计中移动，沿实际消费者找回。
- 未填写新字段的现有项目保持原样。真实正文、含 Ruby/着重号的文字记录、选项与键盘焦点一起检查，不只画静态卡片。

### 定向验收

- 公开读取→修改→重读、非法数据拒绝且正文/记录不变；Editor 草稿→撤销/重做→保存重开，新值保持。
- 同一合法皮肤/字体进入真实共享 Player、Editor 预览与 Windows 导出游戏；缺图和素材改名得到准确结果。
- 中文长句、Ruby/着重号和 140% 字号在对应内容框内可读；原来可滚动的正文不被新内边距/装饰挡住。
- 窄窗口、窗口缩放下九宫格不拉坏边角，文字和按钮命中区一致。装饰变化不改变批准、保存或剧情命令。

## 6. U2：交互状态与页面进出场

### 选择的实现范围

只支持正常、悬停、键盘焦点、按下、禁用的视觉状态，以及有限淡入/位移/缩放的入退场组合。不是 Web CSS 引擎，不允许状态样式变更剧情动作、节点身份、布局尺寸或绑定表达式。

- 基础样式之后按当前交互状态覆盖；按下优先于悬停，禁用优先于可执行状态；键盘焦点标记独立保留，不能被低对比度皮肤隐藏。
- 事件仍派发到现有按钮/动作路径。禁用按钮不能因动画层收到点击而执行，状态切换不额外触发动作。
- 打开菜单时先取得原有暂停/输入所有权，再播放菜单入场；暂停世界不暂停菜单自身动画，不重现曾经“菜单透明但语义已打开”的问题。
- 关闭/换页遵守原返回栈与焦点恢复；旧画面可以退出演出，但不能继续接收点击。快速开关、读档、新游戏、销毁会取消旧动画，迟到回调不得复活旧页或重复推进。
- “减少动态”直接采用静态终态；不缩短剧情等待、不跳过选项、不改变自动阅读规则。
- 不把界面入场动画写进存档；恢复后按原页面状态稳定呈现。动画调度接既有 Renderer 生命周期，不另起常驻轮询或第二个播放时钟。

**GPT：** 当前页面/可执行状态、暂停与销毁契约、必要调度端口及定向生命周期测试。

**Claude：** 状态样式与动画的可见实现、设计器预览、键盘/鼠标反馈；同一状态只取一次真实数据，不根据按钮文字猜状态。

**主要入口：** U1 入口、`packages/host/src/player-shell-controller.ts`、`player-shell-slots.ts`、`packages/renderer/src/runtime/presentation-controller.ts`、`frame-scheduler.ts` 及现有 `menu-entrance-pause` 检查。

**验收：** 动态场景开菜单后世界冻结而菜单正常出现；入场结束能休眠；鼠标/键盘各执行一次；连续开关/读档后无旧回调；减少动态下功能相同；所有变体均不把前端动画完成当成游戏业务完成。

## 7. U3：复用现有主题与界面片段，不新建市场

目前 `ui-sharing.ts` 已支持完整主题和单页片段，并处理变量/素材依赖。本单元只把 U1/U2 纳入现有能力，补清真实使用体验。

- 完整主题携带必要的新样式、交互状态、动画及所需图片/字体；片段保持原来“继承目标主题/字体”的合同。不偷偷把整部作品、存档或插件代码装进去。
- Claude 提供应用前预览和明确范围：哪些页面/组件会变、哪些保留、哪些资源缺失或冲突。确认前不修改目标草稿；导入资源仍走现有导入路径，不覆盖同名不同内容的素材。
- 作者可把自己的成熟界面另存后用于下一部作品。新字段的依赖由公共层计算，前端不维护第二份资源清单。
- 不新增在线模板商店、自动更新、主题继承链或脚本主题。若格式实际需要破坏性变化，先说明具体受影响共享包，不私设迁移兼容层。
- 一套完整样式至少覆盖标题、对白、选项、系统菜单、存读档、设置、文字记录和鉴赏的正常/焦点/禁用/空状态；不是每页另起一套风格。图像和字体采用项目已有合法资源或明确新授权资源，不搬 LetsGal 资产。

**验收：** A 项目配置→导出主题/片段→B 项目预览应用→保存重开→实际游戏显示。缺变量、冲突资源、坏字段拒绝后原 B 项目仍可用；主题不改变剧情、存档身份、插件信任或玩家设置。沿 `packages/editor/test/ui-sharing.test.ts` 和 U1/U2 的受影响真实页面补测即可。

## 8. E1：把既有演出复用能力做成作者工具

### 核心取舍

**复用现有舞台 composition 和时间轴 V2 clip/targets，不再做一个预设解释器。** 首批只服务实际常用的入场、退场、镜头靠近与一组场景布局；示例数量不充当完成标准。

### 作者流程

1. 在已做好的时间轴或舞台布局上选择“用于其他场景”。
2. 选择真实源片段/布局，将其人物目标映射到目标场景中的人物，预览实际受影响对象。
3. 以引用使用：继续消费原 timelineId 与 targets；修改源片段会影响引用它的地方，界面要先列明。
4. 需要只改这一次时，用原创建/修改能力另存为独立片段再引用；不得在实例上暗藏第二份难以察觉的覆盖数据。
5. 修改仍进入现有草稿、历史及保存保护。场景布局与时间轴是两个不同对象，不能把“保存布局”宣传成已保存完整人物动作。

### GPT 工作

- 核对现有 timeline/stage 公开读写是否足够支持上述路径；能用就不增加能力号。只补实际缺少的引用位置、目标映射和影响查询。
- 保留 `atMs`、重复/间隔、targets 的现有含义；循环引用、缺片段、错误目标、实际缺素材均明确拒绝。源头改名更新真实引用，不全文替换正文。
- 创建独立副本要连同必要依赖核对，按原变更会话提交；多个文件不可出现正文已写而引用丢失的半成品。
- 该功能若经过既有候选操作，应完整使用现有前置条件、依赖、冲突与重放事实；某新操作未接组合时明确 direct-only，候选在落盘前拒绝，不能假装可组合。

### Claude 工作

- 在原时间轴/舞台入口中补“复用、目标对应、查看引用、另存独立片段”，使用现有布局和预览，不另开资产治理工作台。
- 人物和素材选项读取真实目录；显示中文名称和明确的目标身份，缺失项不能用另一张图顶替。
- 展示将修改的实际范围；取消不写稿，应用可撤销/重做。预览使用同一时间轴，不制作一个仅供动画演示的替代播放器。

**主要入口：** `packages/core/src/timeline.ts`、`stage.ts`；`packages/authoring/src/timeline-operations.ts`、`stage-operations.ts` 与相关引用分析；`packages/editor/src/timeline-model.ts`、`panels/timeline-panel.ts`、`stage-workspace.ts`、`stage-editing.ts`。

**验收：** 同一片段用于两个场景且绑定不同人物，源修改作用于两处；独立副本修改只作用于一处；命名/引用/撤销/重做/保存重开真实一致。播放中暂停、快进、回退和读档遵守已有舞台属性归属；重复 clip 按声明次数执行，不能因恢复/取消额外重放声音或遗留回调；插件项目原正式续接禁令继续有效。

## 9. E2：常用人物演出方案，不引入隐形持续规则

报告中“设置一次，后续人物自动遵守”的便利值得借鉴，但 Surdet 不能因此增加一套不进快照的隐式规则。

本轮选定更小且可解释的路线：

- 发言突出继续使用既有说话焦点，不再新增相同目的的指令。
- 入场、退场和镜头方案建立在 E1 的片段引用上。作者为选定的一段内容应用方案，先看将插入/调整哪些真实指令与引用，再确认写入。
- 显式已有动作优先，不悄悄覆盖作者精调；有冲突的步骤定位出来由作者决定，不猜谁该淡出、谁该站中央。
- 方案应用后是可查看的普通项目数据，不是编辑器内存里的隐形运行模式。后续修改走原场景/时间轴操作，Agent 读取到同一事实。
- 首版不支持跨场景持续、自动影响未来新写台词的全局规则；不把编辑器便捷操作伪装成已经实现 LetsGal 全套立绘规则系统。
- 参数表单只暴露当前方案真实支持的值与资源。已有指令支持变量时沿用其表达式语义，不擅自把所有演出数值升级成可执行表达式。

**GPT：** 公共操作的预览/应用、源定位与冲突语义，复用现有事务和焦点恢复规则。

**Claude：** 方案选择、简短真实预览、冲突定位和明确的应用范围；不堆成每句几十个开关。

**验收：** 两角色交替对白、旁白和带现有精调动作的内容，应用后不重复指令、不覆盖精调、可完整撤销且 LF/CRLF 保持；保存后 Agent 和成品运行看到同一演出。取消或过期引用时项目不变。

## 10. L0：长篇作品性能先测事实

### 固定问题，而不是先承诺懒加载

当前已确认“启动读取编译全部场景”，但它对真实耗时的贡献未知。已完成的字体读取复用继续保留，不反复证明已过结论。

在现有隔离材料中选择两种直接相关负载：一个当前小作品基线、一个长篇规模项目。长篇若缺真实合法内容，可使用明确标注的合成剧本文本；记录场景数、文本大小、平均/最大场景、跨场景调用深度和素材条件，不把复制字符串称为完整商业游戏。

尽量保持素材、字体、插件、设备和构建条件一致，仅变化当前调查的剧本规模。分别记录：

- 进程启动到可操作标题；点击开始到首句和首个可见稳定画面；二者不能混成一个数字。
- 内容清单读取、场景读取、解析编译、字体准备、首屏资源、Renderer 初始化的实际阶段耗时。
- 首次跨场景、再次进入同一场景、读档到未访问场景及其调用栈恢复的耗时。
- 实际驻留文本/编译场景数量及可取得的内存数据；不能用源文件体积代称内存。

不在本规划编造毫秒承诺或以最好的单轮决定方案。复用现有性能方法选择足够区分波动的定向测量，冷暖条件分开记录；重复次数按实际证据需要确定，不设硬配额。

### L1 进入条件

- 若场景读取/编译不是主要成本，先处理实测瓶颈；把“暂不做 L1”连同证据记在本节，不为实现报告清单而改变 Core。
- 若成本随场景规模显著增长、占据关键等待且可通过延后未访问场景降低，才进入 L1；先冻结同机前后比较方法和可接受的切换/恢复成本。
- 可以做标题前后初始化顺序的小调整就满足需求时，不直接上缓存池、Worker 群、并发预取或章节调度平台。
- 旧 `sceneP95Ms` 正式资格化是另一项未完成事实。L0 或新加载方案改善不能把它改为 PASS；既有正式脚本若与本地红线冲突仍不运行，也不改阈值绕过。

**完成标准：** 留下能回答“慢在哪里、L1 是否值得做、下一步改哪个调用”的阶段数据和结论。不要求整仓回归，不建立通用性能治理设施。

## 11. L1：必要时的按需场景加载合同

以下是实施前必须满足的设计约束，不代表当前已有接口或已获准执行。

### 内容与索引

- 保留 `.gal` 与场景/标签的现有身份。导出时仍检查整部作品的语法和静态引用，不能把未访问章节的错误从导出检查里藏掉。
- 成品只在轻量目录保留寻址和必要元数据，正文按场景加载；不增加内容哈希文件名、摘要清单或在线 CDN。导出端与通用运行时在同一 PR 组升级，不额外维护旧新加载器双轨。
- 场景目录和正文不得来自不同预览修订。已保存来源、当前草稿和候选仍保留原身份/失效规则，不能用磁盘实时读取把旧预览偷偷拼成新版本。
- 若现有公开内容清单确有仍在使用的外部消费者，实施前列清具体调用方与影响，交 Owner 决定破坏性范围；不凭“内部接口”假定没人用，也不自行加兼容分支。

### 运行与失败

- 复用一个 Interpreter/SceneRegistry，不另建异步剧情解释器。进入未加载场景前进入明确等待状态，资源就绪后才执行该场景的第一条指令。
- 玩家在加载期间的点击、自动阅读和快进不能越过停点；菜单仍可响应，不在 UI 线程同步阻塞长时间编译。
- 缺文件、读失败和编译失败分别给出真实位置/原因；不得当作结局、空场景或成功跳转。不重复执行跳转前的变量修改/音频/插件命令来“重试”。
- 生命周期复用当前取消信号/运行代际：重新播放、新游戏、读档、切换项目和关闭取消旧请求，迟到结果不能覆盖新局。失败结果不永久缓存，新的合法重试能恢复。
- 不默认做预取。只有 L0/L1 的实际切换数据表明确有必要时，才引入最小有界缓存；淘汰对象不能仍被当前局、调用栈、回退点或并发恢复持有，不能靠无限保留全部场景消除问题。

### 存读档、回退与编辑

- 读档先取得并验证当前场景及实际要恢复的调用链依赖，再提交恢复；任一步失败保留当前局和原好档，不先修改变量再等场景。
- 保留现有存档定位方式，不为懒加载新增“按台词猜位置”、稳定行 ID 或新存档格式。回退到已淘汰场景如需等待，也必须在同一恢复事务内完成。
- 源行试玩、选择重播、剧情检查、插件暂停、自定义文字记录和语言绑定继续使用原语义。Editor 静态全项目检查可以读取全稿，不等于运行时必须提前编译全稿；不要把静态工具改成缺页即误判。
- 导出的 Windows 游戏、共享 Player 与实际 Editor 预览都使用同一场景解析/注册语义，不在本轮分别实现三套加载器。

**主要入口：** `examples/shared/player/player.ts`、`content-player.ts`；`packages/core/src/runtime/scene-registry.ts`、`interpreter.ts`、`save/save-manager.ts`；`packages/host/src/create-host.ts`、恢复相关调用方；`packages/cli/src/windows-export.ts`、`scenario-loader.ts`；Editor 的 `preview-content.ts`、`preview.ts`、源行路径与原生命周期入口。

**Claude 配合：** 只有实际等待需要提示时，按后端真实状态展示加载、重试与失败；不得伪造百分比或通过重新开始游戏掩盖恢复失败。不得自行修改场景加载/保存逻辑。

**验收：** 首次进入未加载场景、跨场景 call/return、读档到未访问场景、回退、取消后迟到响应、首次读取失败后重试、磁盘变稿、实际导出成品全部按合同验证。比较启动收益时同时报告转场/读档成本及内存；不能以测试夹具网络延迟冒充用户磁盘性能。
