# Surdet Asset Center Visual Thumbnails Implementation Plan

> **For agentic workers:** Inline execution is authorized. Optional delegated review may use only `luna_worker`; the primary agent owns architecture, integration, Git commits, push, and completion.

**Goal:** Turn the Asset Center grid into a real visual library with lazy, lifecycle-safe image thumbnails while keeping list mode dense and preserving every existing asset workflow.

**Architecture:** Add one Editor-only thumbnail module that derives a presentation descriptor from existing `ProjectAssetItem` and `DirAsset` facts, then loads only near-viewport images through a page-scoped session. `asset-center.ts` mounts the thumbnail stage in grid mode; `main.ts` disposes it when leaving the workspace. No cache, manifest, database, Authoring change, CLI change, or asset mutation is introduced.

**Tech Stack:** TypeScript, DOM/File System Access API, `IntersectionObserver`, Vite, Vitest, existing Editor CSS tokens.

## Global Constraints

- All controllable temporary files, browser profiles, caches, and scripts go under `D:\surdet-tasks\asset-center-phase3-next`; nothing generated by this task goes to C.
- Primary UI copy is Chinese; stable technical fields remain available only where already exposed.
- No colored selection rail, gradient, glass effect, thumbnail cache, second asset index, or backend write capability.
- Background thumbnails use `cover`; portrait thumbnails use `contain`; avatar thumbnails use `cover`.
- List mode must not read image bytes for thumbnails.
- Every Object URL and observer must be released on success, failure, rerender, workspace exit, and page unload.
- Existing untracked files and protected documents remain untouched. Delete only files whose lack of current responsibility is directly proven.
- Run the smallest sufficient checks once; do not build evidence archives or repeat full suites for appearance.

function releaseUrl(url: string): void {
