# Wave 11：从保存决定到可试玩结果

## 授权与目标

2026-09-13 Owner 授权完整 Goal：保存决定 → 准备试玩结果 → 自动打开结果 → 试玩、批准 → 接上 Wave 10 写回、加载、继续编辑。整案采用和自定义组合均须支持；使用正常绑定项目入口与已保存、核验的真实决定。

允许必要普通实现、相关缺陷修复、本地验证、提交及推送。基线为 `fe9bc4f`，tracked 工作树干净，原未跟踪资料保留。九月托管 CI 暂停；生产数据、音频、发行、全 Editor 重做、下一波和历史改写不在范围内。Owner 仅进行正常体验；不代签 Owner 体验或云端终审。

## 实施顺序与不变量

1. 先打通现有服务 → HTTP → 页面准备 → 自动打开的一条真实纵向路径。
2. 复用原审阅任务中的持久进度和已有计划／integration／结果，补齐整案、混合、重复请求、响应丢失与中断续接。状态无法核实时拒绝另建；身份或基线改变明确报错。
3. 聚焦测试、类型检查、构建和真实浏览器贯通后，记录结果并提交推送。

准备仅操作隔离结果，不批准、不写回来源、不替换候选或剧情、不丢草稿。验收起点只有候选与比较审阅，不提前生成正式计划、integration 或结果。自动打开不要求 Owner 搬编号、找目录。

## 实现结果

整案与自定义混合均已接通完整页面路径。准备入口读取正式决定，并在原比较审阅目录保存进度；依次调用已有计划、隔离执行、差异、校验、模拟、运行和结果审阅服务。页面通过正常绑定项目的 HTTP 接口继续准备，完成后自动打开预先登记、实际生成的结果审阅。只读结果目录适配原有加载器与预览，不要求用户传编号或选结果目录。

同一决定的计划、integration 和结果身份在执行前登记并在重试时核对。响应丢失、刷新和后台退出后先查持久状态；已完成的步骤复用，旧进程租约按原规则确认失效后继续。无法核实、来源基线改变、候选身份改变、integration 被另行编辑或已关闭均明确停止，不创建替代结果。结构化错误沿真实服务、HTTP、客户端和页面保留。

准备与批准、写回分开；自动打开保留当前草稿。继续使用 Wave 10 的正式批准、明确写回、加载与继续编辑路径。后台重启后的旧窗口确认期到期会自动查询状态，不自动执行写回。

本轮沿真实调用修复了四处相关旧缺陷：组合执行遗漏显式数据目录；已关闭的同计划 integration 被忽略并重新创建；READY 重放未复核最终内容与额外编辑；计划／结果发布中断后无法安全复用。结果文件先完整写入可试玩目录外的临时文件，再以不覆盖的方式发布，半文件不会出现在结果中。既有批准在重开同一结果时保留。

主要落点为 Authoring 的准备协议与执行契约、CLI 的 `review-preparation-service.ts` 及既有 store／Review Authority、Editor 的准备客户端与页面接线。未增加第二套组合逻辑、依赖或任务平台。
