# Surdet Editor 统一壳层与视觉层级底座设计规格

> 日期：2026-09-02
> 阶段：Post-Wave-6 / Pre-Wave-7 前端统一整理窗口
> 位置：素材中心 Phase 3 之后、Frontend Pass 5 之前
> 边界：纯 Editor 前端；不启动 Frontend Pass 5，不启动主线 Wave 7

## 1. 结论

这一轮先重做所有 Editor 页面共同依赖的应用壳层与视觉基础，而不是继续在单个页面上叠样式。

目标是让 Surdet 从“网页表格加深色顶栏”变成稳定、成熟、中文优先的桌面创作工作台：项目身份、当前工作、保存状态、全局命令和九个工作区拥有清楚的主次；字体、间距、控件尺寸和边界规则在所有页面一致；后续预览、审阅、统计与审计迁移可以直接复用这套底座。

本轮不改变任何业务状态、文件格式、Agent 能力、保存语义或各工作区的专业数据结构。

## 2. 真实问题

当前 Editor 已经具备完整应用壳和九个真实工作区，但共同层仍有以下问题：

- 顶栏把品牌、项目、对象、保存状态、操作回执和五个命令平铺成同等权重，窄窗口时容易变成两行按钮带；
- 工作区导航只是连续按钮条，没有创作、验证、管理三类任务层次；
- 中文字号层级不足，小字、技术字和普通正文过于接近；
- 控件高度、间距和边界仍混有旧样式，部分页面看起来像压缩后的表格；
- 旧全局 CSS 仍存在，但已迁移工作区依赖的新 token、组件和壳层没有形成足够明确的覆盖权威；
- 视觉层级过度依赖边框与框体，留白和排版承担的信息组织不足。

## 3. 产品原则

### 3.1 中文优先

- 用户可见的项目、命令、模式、状态和辅助说明使用自然中文；
- `Surdet` 作为产品名保留；内部 ID、文件名和技术键仍按需展示；
- 快捷键作为命令的辅助信息，不与主文案混成一句话。

### 3.2 一个事实源

- 顶栏继续消费现有 `ProjectBarProjection`；
- 模式切换继续消费现有 `state.mainTab` 与同一个回调；
- 不新增项目状态、保存状态、命令总线或第二套导航状态；
- 只重组 DOM 语义和视觉呈现。

### 3.3 克制的桌面层级

- 深色应用栏只承载全局身份与命令；内容区保持温和、清晰、适合长时间阅读；
- 重要性通过位置、字号、字重、间距和对齐表达，边框只用于真实可操作区域；
- 主动作只保留一个高强调入口；撤销、重做、打开等使用低强调样式；
- 不使用渐变、玻璃拟态、卡片墙、彩色左竖线、状态胶囊海洋或装饰性文案。

### 3.4 可持续迁移

- `tokens.css` 是新视觉值的唯一来源；
- `components.css` 负责控件与通用状态；
- `app-shell.css` 负责全局壳层和响应式布局；
- 模式专属 CSS 继续拥有专业工作面的内部布局；
- 旧 `styles.css` 暂作未迁移模式的兼容层，本轮不以大规模删除制造回归。

## 4. 信息架构

### 4.1 顶栏

顶栏分为四个稳定区域：

1. 产品身份：`Surdet / 剧情创作`；
2. 当前上下文：当前项目、当前工作对象；
3. 全局命令：项目、编辑和保存三组；
4. 操作回执：保存事实与即时状态。

快捷键放入独立的 `<kbd>`，视觉上降级。命令仍保留原有 `data-action`、点击回调和禁用逻辑。

### 4.2 工作区导航

九个模式仍全部可见，但按真实任务分为三组：

- 创作：剧本、素材、流程、时间轴、配置；
- 检查：预览、审阅；
- 项目：统计、审计。

分组只影响导航语义与间距，不改变模式 ID、面板 ID 或路由事实。当前模式使用完整表面与完整边界，不依赖单侧彩条。

### 4.3 内容区

- 应用壳不再给所有内容制造额外卡片；
- 模式表面使用统一背景和边界；
- 标题、正文、说明、技术信息分别使用明确字号；
- 输入和按钮达到稳定的桌面点击尺寸；
- 允许留白，不为了铺满画面制造容器。

## 5. 视觉基线

### 5.1 色彩

- 应用栏：中性炭黑，不使用蓝黑后台模板色；
- 内容底：暖灰纸面；
- 主文字：近黑；辅助文字：中性灰；
- 主动作：低饱和陶土红，只在关键动作和焦点使用；
- 成功、警告、危险色只表达真实状态，不承担装饰。

### 5.2 排版

- 正文基线 15px；控件与导航不低于 14px；辅助说明不低于 13px；
- 页面标题 20–24px，栏目标题 16–18px；
- 中文 UI 优先 `Segoe UI`、`Microsoft YaHei UI`、`PingFang SC`；
- 技术内容才使用等宽字体。

### 5.3 间距与控件

- 建立 4/6/8/12/16/20/24/32/40/48/64px 的有限尺度；
- 常规按钮和输入高度不低于 38px；
- 紧凑按钮只用于工具条，不成为全局默认；
- 圆角保持克制，普通控件 4px、容器 6px，不使用大圆角或胶囊。

## 6. 响应式合同

- 1440×900：单行顶栏、完整三组命令、完整模式分组；
- 1024×768：命令移动到第二行，当前项目与状态保持可读，导航可横向滚动；
- 390×844：顶栏按产品、上下文、命令、状态顺序堆叠；主内容不被固定层遮挡；导航可键盘和触控滚动；
- 不伪造移动端专用业务模式，也不隐藏现有功能。

## 7. 允许与禁止

允许修改：

- `packages/editor/src/shell/*` 的纯展示结构；
- `packages/editor/src/styles/tokens.css`、`components.css`、`app-shell.css`；
- 对应 Editor 合同测试和一个轻量真实浏览器检查；
- 本规格、任务书和长期台账的简短阶段记录。

禁止修改：

- Authoring、Core、CLI、Agent Port、Renderer、Host、Shell 生产代码；
- 项目格式、存档格式、保存/撤销/审阅/导入/素材整理语义；
- 各模式专业内部结构；
- 依赖和 lockfile；
- Frontend Pass 5 或主线 Wave 7 的任何实现。

## 8. 验收

- 所有九个模式仍通过原单一回调切换；
- 所有顶栏命令的动作、禁用和快捷键语义保持；
- 当前项目、当前工作、保存状态和操作回执都有稳定语义区域；
- 导航具有三组可访问语义，当前项采用完整表面选中；
- 新底座不存在渐变、玻璃拟态、胶囊泛滥或彩色左竖线；
- 1440×900 与 390×844 实际浏览器检查没有遮挡或不可达主命令；
- Editor 聚焦测试、全量测试、typecheck 和 build 通过；
- 普通提交和普通 push 后 CI 通过。
