## 一、结论摘要

Surdet 前端将彻底放弃当前以浅色卡片、统一圆角、彩色左竖线、紧凑三栏和等权信息为主的视觉语言，建立一套面向完整游戏创作流程的桌面工作台。

新界面采用已经批准的 A5“版本案卷”方向，但不把整个产品做成档案管理系统。它只借用版本案卷最适合 Surdet 的能力：稳定对象身份、来源、版本、审阅、决定与回执。普通创作模式始终以场景、脚本、流程、时间轴、配置和游戏预览为主；既有前端数据中真实存在的版本、哈希、指纹、原始 JSON 与来源事实默认降级到上下文抽屉或技术详情，前端不得推导缺失事实。

本重构覆盖整个 Surdet 前端，而不是单独覆盖审阅页：

1. Editor 全局应用框架；
2. 块编辑；
3. 流程图；
4. 时间轴；
5. 配置；
6. 预览；
7. 审阅；
8. 统计；
9. 审计；
10. 未打开项目、加载、空内容、错误、只读回执、窄窗口等横切状态；
11. Renderer 玩家界面、系统菜单、存读档、回看、鉴赏、地图、商店、战斗、Loading 等前端表面；
12. Host/Shell 对新 Editor 与 Renderer 的消费回归；当前两个包不存在可独立换皮的前端视图，因此不把主进程、IPC 和状态协调伪装成视觉重构范围。

本轮不修改 Authoring、Core、CLI、Agent Port、项目格式、存档格式、审阅回执格式、错误码、指纹算法、文件持久化语义或运行时状态机。若施工发现某个视觉目标必须修改这些边界，必须停止并拆成新的独立任务，不能以“前端重构”为由顺手扩张。

## 二、已确认事实与产品裁决

### 2.1 已确认事实

- Editor 是一个单页应用，当前包含“块编辑、流程图、时间轴、配置、预览、审阅、统计、审计”八个主模式；
- 玩家预览是独立 iframe，实际玩家画面来自 Renderer，因此只重写 Editor 样式不能覆盖全部前端；
- 现有 Editor 大量复用单体全局 CSS、命令式 DOM 和单例状态，流程图、配置地图与拓扑图中还有内联 SVG 颜色；
- 当前彩色左竖线不只存在于块编辑，还存在于场景选中、校验问题、审计信息、审阅安全组/冲突/依赖、时间轴选中和错误状态；
- 预览 Canvas 已有双轴居中、不拉伸和因果轨迹独立滚动合同；
- 审阅页已有稳定对象身份、决定回执、批准/退回互斥、只读重开和 stage 预览合同；
- 当前功能已经积累大量行为测试与语义锚点，视觉重构不能把测试失效误写为“测试过时”。

### 2.2 已批准产品裁决

- 选择 A5“版本案卷”作为全局结构方向；
- 采用“创作优先版”，而非“档案管理版”；
- 用户层以自然中文、作品内容和当前任务为主；
- Agent、审阅者和高级用户仍可读取专业 ID、fingerprint、provenance、error code 与原始证据；
- 删除所有彩色左竖线；
- 不复用旧视觉系统；
- 不修改已有业务功能；
- 不大动后端，不建立第二套业务真相；
- 施工 AI 负责本地实现、测试和提交；远端审核 AI 直接审核 GitHub 上的真实代码，避免用户转述技术事实。

### 2.3 与既有规格和台账共存

本规格是全前端体验重构的唯一新增设计依据，但不覆盖、改写或替代已经生效的架构与行为合同。它已经完整复述本轮需要的产品裁决，远端审核不依赖任何未跟踪本地文档。施工与审核同时参考：

- 本地未跟踪的长期路线台账只作为本规格形成时的治理输入，其中“双向因果创作台”、先设计后施工以及 Editor 与 Agent 共用同一内核的结论已经写入本规格；不得为了补齐引用擅自暂存该台账；
- `docs/superpowers/plans/2026-08-24-pre-wave-5-editor-foundation-polish-wave-1.md` 中预览双轴居中、保持宽高比、因果轨迹独立滚动以及不建立第二套预览运行时的合同；
- `docs/superpowers/specs/2026-08-26-human-agent-review-workbench-stage-6-wave-6-design.md` 中 Authoring 单一语义真相、中文优先、技术信息按需下钻、Owner 回执权限和真实 stage 结果预览的合同；
- `docs/superpowers/plans/2026-08-30-wave-6-owner-review-comprehensibility-repair.md` 中人类摘要、稳定来源绑定、完整候选内容和技术详情分层的合同；
- `docs/architecture.md`、根 `README.md`、各 package export 与真实源码共同证明的职责边界；不得把任一概览文档单独当成完整架构事实。

本规格不得被追加进 Wave 6 Execution Ledger，也不得借视觉重构更正或重写历史证据。历史任务书、交付报告、失败 artifact 和既有审阅回执保持原样；`docs/README.md` 只允许在最终闭合波更新当前阶段与 canonical 入口，不把候选样图和施工中间稿全部写入长期文档入口。

## 三、目标与非目标

### 3.1 目标

1. 让 Surdet 第一眼成为完整、可信、可长期使用的桌面游戏创作工具，而不是 AI 生成的后台网页；
2. 让每个主模式拥有与其任务匹配的独立工作面，而不是八个页面共用同一套卡片骨架；
3. 让普通创作者默认看到内容和行动，让技术事实始终可查但不平铺；
4. 建立稳定的排版、空间、颜色、选中、焦点、状态和动作体系；
5. 保留所有现有能力与语义合同；
6. 允许分阶段迁移，每个阶段都保持可运行、可测试、可回退；
7. 为未来页面提供明确反 AI 约束，防止再次退化为通用模板。

### 3.2 非目标

- 不重写引擎运行时；
- 不更改项目、存档、脚本或时间轴文件格式；
- 不重做 Agent Port 或 Authoring API；
- 不改变审阅决定、批准、退回和 apply 的权限边界；
- 不增加内嵌模型、推荐模型或生成式 UI；
- 不借机重构无关算法；
- 不增加没有当前调用方的主题插件、皮肤商店或设计系统运行时；
- 不以“反 AI”为理由牺牲可访问性、熟悉操作或现有快捷键；
- 不用一次大爆炸提交替换全部前端。

## 四、纯前端边界

### 4.1 允许修改

实现计划可以在以下范围内安排前端修改：

- `packages/editor` 的 HTML、CSS、前端 TypeScript、面板组织和前端测试；
- `packages/renderer` 的视图、主题、布局、样式、玩家控件和前端测试；
- 与上述前端行为直接对应的 E2E、DOM、布局和可访问性测试；
- `packages/host` 与 `packages/shell` 只作为消费方运行回归；只有代码中已经存在、可明确证明为纯显示的 seam 才能另行列入某一波白名单；
- 本设计规格、实施计划与最终交付报告。

允许重组前端 DOM、CSS 文件和视觉组件，但必须保留或同提交迁移现有语义锚点、事件合同与测试。

### 4.2 禁止修改

除非项目所有者另行批准新的独立任务，否则禁止修改：

- `packages/authoring` 生产代码；
- `packages/core` 生产代码；
- `packages/cli` 生产代码及 Agent Port；
- 公共 schema、capability registry、错误码、指纹、provenance、comparison、plan、receipt 或 commit gate；
- 项目格式、脚本语法、时间轴格式、存档格式和迁移逻辑；
- 文件写入、EOL、备份、恢复、lease、并发、apply 与 commit 语义；
- Starter 内容、游戏资产、剧情文本和示例项目；
- 依赖和 lockfile，除非单独证明现有依赖无法满足明确需求并取得授权。

### 4.3 边界冲突处理

如果视觉实现发现后端投影缺少字段，不得在当前任务中扩充后端。先确认能否使用现有前端数据组合或渐进披露解决；若不能，记录阻断、保持现场并申请一个独立、最小的公共合同任务。

## 五、设计母题：创作优先版本案卷

### 5.1 借用什么

- 稳定的应用框架；
- 清晰的项目、章节、场景与版本层级；
- 审阅工作区中已经存在、可追溯但不喧宾夺主的来源、决定与回执；
- 适合长内容的连续稿件；
- 严谨的校样、批注、决定与回执；
- 直线、编号、缩进、留白与表格规则形成的秩序。

### 5.2 明确不借用什么

- 牛皮纸、咖啡渍、印章拼贴、木纹文件柜等复古拟物；
- 整站宋体与米色背景；
- 每个对象都显示档号、哈希与版本；
- 行政审批口吻；
- 把普通写作强迫成版本审计；
- 为了主题统一而牺牲流程图、时间轴和游戏预览的专业工作面。

### 5.3 核心心智模型

```text
作品
  -> 章节与场景
  -> 当前创作对象
  -> 与当前对象有关的角色、资源、变量和校验
  -> 按需展开的版本、来源、因果与技术证据
```

普通用户永远从作品内容进入；版本与证据是底座，不是首页。

## 六、前端架构

### 6.1 四层结构

1. **视觉基础层**：颜色、字体、间距、边界、焦点、状态、运动和密度 token；
2. **应用框架层**：项目栏、八模式导航、命令区、状态栏、可调整工作区；
3. **工作区原语层**：目录、主画布、Inspector、底部 Dock、命令条、空状态、错误状态；
4. **模式专属层**：剧本稿件、流程画布、时间轨道、配置台账、预览舞台、审阅校样、统计摘要、审计记录。

这些层共享语义，不共享同一种页面骨架。流程图不能被强制塞进稿纸；时间轴不能被渲染成配置表；预览不能被右栏和因果轨迹压缩。

### 6.2 CSS 与组件边界

- 不继续让一份全局 CSS 同时控制所有页面的细节；
- 全局 token、应用框架、共享交互和各模式样式分离；
- 全局 `button`、`input`、`.empty`、`.dim` 等宽泛选择器逐步收口为语义明确的组件类；
- 流程图、配置地图和拓扑图中的内联色值迁移到前端主题 token；
- 样式重构不得复制第二套状态机或数据映射；
- 视觉组件只接收现有前端状态，不计算新的业务结论。

### 6.3 渐进迁移

新旧页面不得长期并存为两套产品，但施工期间允许按模式逐步迁移。每个阶段必须保持应用可用，已迁移页面使用新框架，未迁移页面通过临时外壳接入，不复制业务逻辑。

## 七、全局应用框架

### 7.1 项目栏

常驻显示：

- Surdet 产品名；
- 当前项目；
- 当前文件或工作对象；
- 已保存/未保存/部分失败状态；
- 打开项目、撤销、重做、保存；
- 搜索或命令入口；
- 仅在 Electron 使用真实自绘标题栏时显示必要窗口控制；浏览器 Editor 不绘制假的桌面标题栏按钮。

项目栏不显示营销口号、欢迎语、装饰性副标题或与当前任务无关的说明。

### 7.2 八模式导航

八个模式始终可定位：

```text
剧本 / 流程 / 时间轴 / 配置 / 预览 / 审阅 / 统计 / 审计
```

宽窗口采用左侧纵向分类；窄窗口可折叠为带文字的模式选择器。选中模式使用整块反白、图标与文字共同表达，不使用左侧彩色竖线。

### 7.3 工作区拓扑

默认桌面拓扑为：

```text
模式导航 | 模式目录/工具 | 中央主工作对象 | 上下文 Inspector
                               |
                          可折叠底部 Dock
```

中央主工作对象始终占最大面积。左侧只承担导航、对象目录或工具；右侧只显示当前选择的补充信息；底部只显示时间、因果、证据、问题或历史。没有内容时允许留白，不能为了“填满界面”制造建议卡片。

### 7.4 动作位置

- 全局保存位于项目栏；
- 对象级动作位于对象标题或对象末尾；
- 审阅决定位于对应决定区；
- 时间轴播放位于时间轴命令条；
- 预览播放位于舞台控制区；
- 不允许悬浮动作遮挡内容；
- 每个动作作用域最多一个高强调主动作：项目栏保存属于应用级作用域，工作区可以另有一个与当前任务直接相关的主动作，但两者不得相邻竞争或使用相同文案。

### 7.5 资产目录与素材操作

资产目录是跨模式创作能力，不得在重构中被当成普通右栏噪音删除：

- 保留项目目录扫描、分类、使用情况、悬停预览、复制 key 和插入指令；
- 用连续目录、分组行和明确的素材预览区重新组织，不做等尺寸素材卡片墙；
- 普通用户优先看到中文类型、素材名称、缩略预览和使用位置，稳定 key 按需显示；
- 素材选择与插入必须继续写入原有编辑路径，不新增第二套资产索引、缓存或插入逻辑；
- 无素材、缺失素材、重复引用、预览失败和窄窗口都必须有可读状态。

### 7.6 成熟创作工作台完成度基准

项目所有者提供的高密度桌面创作工作台参考图，作为“完成度、层级和协同工作面”的基准，不作为字段、品牌或布局像素的照抄规格。最终界面必须吸收以下真实能力：

- 在已打开项目且存在对应数据时，场景/素材目录、连续稿件、当前对象上下文、实时预览或状态摘要、时间/因果 Dock 能围绕同一工作对象协同，而不是彼此无关的空白页面；
- 中央稿件或当前专业工作面始终拥有最大可读面积，其他区域通过稳定分栏、折叠与 Dock 从属，不用等尺寸卡片把信息铺平；
- 每个模式必须明确唯一的一级工作对象、有限的二级工具和按需出现的三级证据；标题、说明、状态、表格、动作与技术信息不得通过等高、等宽、等边界处理获得相近视觉权重；
- 信息密度服从任务而非几何对称：允许一个重要工作面占据大部分空间，允许次要区域留白、折叠或只占一行；禁止为了填满栅格而制造容器、说明、统计或假数据；
- 边界只用于真实的滚动、选择、输入、对照或可独立操作区域。普通标题和说明依靠字号、字重、间距与对齐形成层次，不为每段文字追加相同面板壳；
- 1440×900 及以上优先呈现高信息密度的桌面工作面；1280×720 与 1024×768 通过可键盘操作的折叠/恢复保持主任务，不允许用溢出覆盖导航或制造三条互相争抢的长滚动栏；
- 若剧本模式提供预览或时间轴 peek，只能消费现有 preview/timeline 状态与回调；DOM 中不得同时存在两个运行 iframe、两份 trace 状态或两套 timeline edit state；
- 同一场景选择在项目栏、目录、稿件、Inspector、预览/时间轴联动中必须指向同一既有对象身份，不得为了同屏效果建立第二个选择真相；
- 所有可见命令、章节、时长、版本、协作、评论、通知、人物数值、状态变化与因果条件都必须来自现有前端投影。当前状态没有对应事实时直接省略，不允许用假数据、文学化占位或后端扩张填满画面。

因此，“像成熟桌面创作工具一样完整”是硬目标；“逐项复制参考图里的虚构产品字段”不是目标。空项目的真实空状态可以留白，但加载 Starter 或真实项目后的最终验收不能仍停留在壳层骨架。

## 八、八个主模式

### 8.1 剧本

- 中央是连续稿件，不是纵向卡片列表；
- 场景标题、旁白、人物、台词、标签、指令、变量和选项通过排版角色区分；
- 类型化编辑与原始行编辑继续可用；
- 场景目录显示章节、场景、dirty 和校验摘要；
- 右侧只显示当前场景或当前块相关的角色、资源、变量、引用和问题；
- 行号和当前数据中已经存在的技术身份默认收起；用户主动展开“技术详情”后才出现；
- 普通剧本页不新增、推导或伪造版本树、来源链和持久修订记录；这些数据只有在既有前端投影真实提供时才能展示；
- 当前块使用整段浅底、完整轮廓、段落编号和明确文字，不使用彩色左竖线。
- 在 1440×900 及以上、真实项目已加载且关联数据存在时，剧本模式应形成左侧场景/素材目录、中央连续稿件、右侧上下文/预览区、底部可折叠时间或因果 Dock 的协同工作面；中央稿件保持最大区域，所有联动复用既有单一状态与运行时。

### 8.2 流程

- 中央是全尺寸故事流程画布；
- 入口、场景、标签和不同边语义仍可辨认，但颜色不承担唯一语义；
- 选中节点使用完整轮廓、标题反白和 Inspector 状态；
- 平移、缩放、小地图、跳转、右键、拖拽建链全部保留；
- 错误和警告通过节点符号、文字和完整边框表达；
- 不在画布上堆叠通用白色卡片。

### 8.3 时间轴

- 中央是专业多轨时间工作面；
- 左侧为时间轴/轨道目录，右侧为当前 Cue Inspector，底部或中央包含标尺与播放头；
- Cue 拖动、调整时长、类型参数、播放、删除和 dirty 状态保持；
- 无效 JSON 必须继续 fail-loud；
- 当前 Cue 采用完整外框、把手和 Inspector 同步，不使用左竖线；
- 轨道颜色受限且同时使用轨道名、动作图标和文字。

### 8.4 配置

- 配置页按角色、变量、成就、日历/地图、成长、事件、鉴赏和名词表组织；
- 普通字段使用结构化台账、定义列表和分组表单，不全部放入卡片；
- 地图进入专属全尺寸画布；
- 高级 JSON 或内部 ID 默认折叠；
- 配置撤销历史继续独立于普通编辑历史；
- 导入、导出、保存与校验语义保持。

### 8.5 预览

- 游戏舞台是绝对视觉中心；
- Canvas 双轴居中、保持宽高比且不拉伸；
- label 起点、快进、播放和重载位于舞台控制区；
- 诊断信息位于稳定消息区；
- 因果轨迹放在独立可折叠 Dock，拥有自己的滚动，不得挤压舞台；
- 轨迹对象定位、Timeline Cue 联动和 iframe generation 隔离保持；
- 预览页不使用版本案卷视觉包裹游戏画面。

### 8.6 审阅

- Comparison 与 Result 两种工作区继续严格区分；
- 相同内容合并展示来源，不重复成多个卡片；
- 真正差异优先，次要证据渐进展开；
- 候选显示字母只负责本次阅读，保存仍绑定稳定 candidate/unit 身份；
- 决定动作位于冲突决定区，不能浮在滚动内容上；
- 保存中冻结控件；失败后恢复；回执重开保持原选择和只读；
- 批准与退回互斥；探索性修改继续禁用批准；
- 技术身份、payload、fingerprint 和证据路径可以折叠，但不能删除。

### 8.7 统计

- 不再使用等宽统计卡片矩阵；
- 只重排现有统计模型已经提供的场景数、字数、台词、选择、结局、CG 和预计时长；
- 优先把现有统计组织成可扫描的编辑摘要和紧凑数据表，不新增、推导或伪造未完成场景、死路、路径覆盖率、未引用资源或待审数量；
- 图表数量保持最小，只在数据关系确实比表格更清楚时使用；
- 空项目使用真实空状态，不渲染一排零值卡片。

### 8.8 审计

- 重新组织现有称谓、术语和配对审计结果，不把审计页伪装成不存在的修订日志；
- 只有既有审计模型已经提供的字段才能进入筛选、排序、定位和摘要；
- terminology 发现仍可定位原文并加入名词表，现有 audit pair 关系继续可读；
- 不新增、推导或伪造时间、操作者、来源、动作历史和版本记录；
- info、warning、error 使用图标、中文状态和整行层级，不使用彩色左竖线；
- 技术原文按需展开。

## 九、Renderer 与消费方边界

### 9.1 Renderer 玩家界面

Renderer 不继承“档案管理”外观。玩家界面以游戏内容为主，仅共享以下基础：

- 清晰中文排版；
- 稳定焦点与选中状态；
- 克制的系统控件；
- 一致的错误、确认和禁用语义；
- 无渐变玻璃、无卡片海、无无意义装饰文案。

普通对话、选项、回看、提示、命令栏、标题、结局、系统菜单、设置、存读档、鉴赏、战斗、地图、商店、据点、视频与 Loading 均需纳入视觉重构清单，但不得改变 Renderer 命令、状态转换、存档接线或游戏内容。

Renderer 是玩家正在经历故事与玩法的舞台，不沿用 Editor 的案卷、Inspector、三栏工作台或技术元数据语言。下表只允许排版既有 view/command 投影真实提供的字段；字段缺失时省略对应区域，禁止从 ID、label 或场景内容猜测业务语义，也禁止借视觉重构新增筛选、跳转、搜索、统计、分页、危险级或任务追踪。

| 表面 | 主视觉对象 | 信息层级 | 动作位置与返回 |
|---|---|---|---|
| ADV | 全幅背景、角色立绘与演出画布 | 当前画面 → `text/speaker/choices` → command rail 与 awaiting 状态 | 推进使用既有确认区；既有命令项收在对话框下沿；系统入口固定角落 |
| NVL | 中央连续文本页，画面作为底层氛围 | `speaker/text` 连续阅读列 → 既有 choices 与 awaiting 状态 | 选择紧随相应文本；推进在文本页下沿；不新增章节元数据 |
| 标题 | `backgroundKey` 对应背景与作品标题 | `title` → 可选 `subtitle` → `items` | 菜单严格按既有 items 排列并表达 enabled；初始焦点沿用现有默认动作；根标题无伪造返回来源 |
| 结局/章节结束 | 单一收束层 | 显示 `showEnding(text?)` 提供的 text；缺省时继续显示既有 `THE END` | 不新增题图、CG、说明、按钮、分享或评分；离开方式完全沿用既有调用方 |
| Loading | 既有加载层 | `current` → `completed/failed/total` 真实进度 → `done` | 无新增动作；禁止假百分比、取消/跳过、伪终端日志和文案填充 |
| 系统菜单/设置 | 被压暗但仍可辨认的当前场景 | 菜单只显示既有 `id/label` 顺序；设置只显示既有 row 投影 | 单层覆盖；不得根据 id 文本猜测危险级分区；关闭按既有 onClose/返回栈恢复 |
| 存档/读档 | `thumbnail` 或槽位内容摘要 | `mode` → 槽位 `label/kind/updatedAt/playTimeSec` → `empty/backupAvailable` | 槽位列表或真实缩略网格占主区；动作只来自现有 handlers/options；不新增损坏状态或分页 |
| 回看 | 连续可读的对话记录 | `text` → `speaker` → 可选 `voice`；既有搜索按当前 query 工作 | 滚动为主；语音回放靠近对应条目；禁止新增标记、每句卡片化和开发信息 |
| 鉴赏 | CG、音乐、文本回想等既有内容本体 | 内容预览 → 解锁状态 → 现有 `cgs/music/texts` 分类 | 缩略目录与大预览形成主从；只保留现有分类和播放/回想动作 |
| 地图 | 地图图像与交互地点 | `date/turn/ap/maxAp` → 节点 `name/visited/enterable/apCost/isBase` | 进入动作锚定可进入节点；不新增地点说明或旁侧卡片清单 |
| 商店 | 商品或店铺主题画面 | `gold` → 商品 `name/price` → 可选 `message` | 商品区为主；购买与关闭只使用现有回调；不新增属性、数量或筛选 |
| 战斗 | 战场、单位与即时演出 | `turn/actingTeam` → units 的 `hp/skills/canMove` → 可选 message → `finished/winner` | 攻击、跳过、移动只使用既有 handlers；目标选择直接映射战场，不退化为后台表格 |
| 据点/基地 | 既有基地命令面板 | `date/ap/maxAp` → command `name/apCost/enabled/remaining` | 命令使用一个稳定列表，执行/关闭只走现有回调；不新增场景热点或资源面板 |
| 视频 | `source` 对应的全幅视频 | 只显示视频内容与当前实现已有的播放投影 | 不新增控制条或跳过规则；结束只调用既有 `onEnd` 并沿原流程恢复 |
| 隐藏 UI | 当前剧情、战斗或视频画面 | 纯画面；必要字幕按既有规则保留 | 非必要 chrome 退出焦点树；再次输入按既有合同恢复，不改变业务状态 |

所有覆盖表面继续使用既有 `returnStack`：取消/B/Esc 先关闭最上层，再返回真实来源；不得硬编码回标题或剧情。进入表面时提供可预测初始焦点，关闭后恢复原控件或原游戏焦点。键盘、gamepad 与指针共享同一动作模型；hover 不能成为唯一信息入口。`interfaceHidden`、`videoActive`、saving、loading、returning-title、失败恢复和禁用状态都必须进入页面矩阵，离屏控件不得继续接收输入。

除标题、存读档、回看和鉴赏等天然独立表面外，剧情或玩法画面始终占绝大多数视口。系统层优先覆盖安全区，不永久切走舞台空间；同屏只保留一个主行动区，正文、字幕和焦点项在常见宽高比与缩放下不得被遮挡。

### 9.2 Renderer 主题合同

- `DEFAULT_RENDERER_THEME` 与 `createRendererTheme` 是现有公开主题边界，不得被绕过或复制；
- `createRendererTheme` 继续按现有字段级合并工作：项目显式覆盖的字段保持原值，未覆盖字段会继承新默认主题，因此部分 override 项目可能只在未覆盖部分发生视觉更新；不得把这种真实合并语义错误描述为“自定义项目整体不变”；
- 不改变主题对象 shape、字段级合并顺序、显式 override 优先级或消费 API；
- Editor 预览继续消费真实 Renderer 和相同主题合并路径，不建立“编辑器专用假播放器”；
- Starter 内容与资产不变，但它在没有显式 override 时可以自然呈现新默认主题；
- 主题验证必须覆盖 override、NVL、backlog、隐藏 UI、视频、operation、returnStack、键鼠与 gamepad 状态，不得只验证一张 ADV 对话截图。

### 9.3 Host 与 Shell

当前 `packages/host` 和 `packages/shell` 没有可独立换皮的前端视图：Host 主要承担 Player UI 状态、槽位与协调，Shell 主要承担 Electron 主进程、IPC、存储与窗口生命周期。本重构只要求它们正确消费新的 Editor/Renderer 构建并通过相邻回归；不得为了凑齐“全前端”范围去改状态协调、IPC、存储、会话清理、全屏、退出或资源所有权。若后续代码基线出现明确纯显示 seam，必须在对应实施波次中单独列出路径、行为边界和回归门，不能凭包名扩大范围。

## 十、视觉系统

### 10.1 色彩与 Token 层级

新设计系统统一使用 `--surdet-*` 命名空间，分三层建立，不允许组件直接各自解释一组裸色值。

**Primitive：**

```css
--surdet-color-paper-0: #F6F7F5;
--surdet-color-paper-50: #FFFFFF;
--surdet-color-paper-100: #ECEFEC;
--surdet-color-ink-900: #1A1E21;
--surdet-color-ink-600: #53616A;
--surdet-color-frame-900: #162832;
--surdet-color-line-300: #D7DBDC;
--surdet-color-line-600: #8E9A9F;
--surdet-color-blue-600: #315B78;
--surdet-color-provenance-600: #6F5A45;
--surdet-color-success-600: #3E6B53;
--surdet-color-warning-600: #9A6728;
--surdet-color-danger-600: #A13B35;
```

**Semantic：** 首版固定以下映射，实施不得自行换色；后续调整必须通过独立视觉裁决更新设计系统决定记录。

```css
--surdet-surface-app: var(--surdet-color-paper-0);
--surdet-surface-panel: var(--surdet-color-paper-50);
--surdet-surface-subtle: var(--surdet-color-paper-100);
--surdet-surface-selected: #E1E8E5;
--surdet-text-primary: var(--surdet-color-ink-900);
--surdet-text-secondary: var(--surdet-color-ink-600);
--surdet-border-default: var(--surdet-color-line-300);
--surdet-border-strong: var(--surdet-color-line-600);
--surdet-action-primary: var(--surdet-color-blue-600);
--surdet-focus-ring: #1E648E;
--surdet-state-provenance: var(--surdet-color-provenance-600);
--surdet-state-success: var(--surdet-color-success-600);
--surdet-state-warning: var(--surdet-color-warning-600);
--surdet-state-danger: var(--surdet-color-danger-600);
--surdet-state-readonly: var(--surdet-color-ink-600);
```

hover、active、focus、disabled、readonly、selected 状态由 semantic token 的透明度、完整边界和文字共同表达；禁止组件直接回到 primitive 裸色。

**Component：** 组件只能从 semantic token 映射，例如 `--surdet-editor-nav-active-bg`、`--surdet-editor-selection-outline`、`--surdet-review-decision-border`、`--surdet-timeline-grid-line`。不得在各模式重新发明 accent、panel、shadow 和 status 色。

Renderer 不直接复用 Editor CSS 变量；它通过既有 `RendererTheme` 字段实现相同语义，并由一份静态映射表说明对应关系，避免建立跨包主题运行时。每个工作区首屏除中性色外最多使用一个主强调色。状态色只用于真实语义，不能同时装饰标题、按钮和背景。

### 10.2 字体

- UI、按钮、导航、表格：`"Segoe UI", "Microsoft YaHei UI", "PingFang SC", "Noto Sans CJK SC", sans-serif`；
- 剧情正文与场景标题：可以使用系统已经提供的 `"Noto Serif CJK SC", "Source Han Serif SC", "Songti SC", serif`，缺失时回退 UI 字体；本轮不为字体新增依赖或打包资产；
- ID、行号、时间、哈希：`"Cascadia Mono", "Sarasa Mono SC", Consolas, monospace`；
- 不允许整站只靠同一种字号和字重；
- 不允许用英文小标题制造“高级感”；
- 中文正文目标字号 15–18px，并允许系统缩放；
- 长稿正文限制合理行宽，避免横跨整个超宽显示器。

### 10.3 间距

以 4px 为计算原子，但实际布局使用：

```text
8 / 12 / 16 / 24 / 32 / 48
```

- 4px 只允许图标内部和极紧密的微对齐；
- 标题与属于它的说明：8–12px；
- 同一功能组内部：12–16px；
- 不同功能组：24–32px；
- 大章节或工作区转换：40–48px；
- 组内间距必须小于组间间距。

### 10.4 边界与容器

- 默认圆角只允许 `0 / 2 / 4px`；
- 禁止 `999px` 万能胶囊，真实开关控件除外；
- 普通信息分组优先使用标题、留白、缩进和细横线；
- 只有具备独立选择、拖动、折叠、操作或状态边界的对象才允许成为容器；
- 禁止卡片套卡片；
- 普通面板无阴影；浮层、菜单和对话框可以使用单一克制阴影；
- 禁止装饰性背景渐变、渐变字、玻璃拟态、发光、悬停漂浮和装饰性 3D；
- 时间轴刻度、透明遮罩、进度或对比度辅助等功能性渐变可以保留，但必须具备明确功能说明、局部作用域和永久测试，不能被复用为品牌装饰。

### 10.5 图标

- 图标只辅助文字，不取代关键操作文字；
- 不为每个图标添加独立彩色底盒；
- 同一层级使用统一线宽；
- 成功、警告和错误同时使用形状、文字和颜色；
- 不使用无法解释的“AI 星光”“魔法棒”“闪烁”等泛化符号。

### 10.6 运动

- 动效只用于面板展开、位置变化、保存反馈、模式切换和焦点过渡；
- 默认 120–200ms；
- 禁止无功能意义的弹跳、漂浮、呼吸光、数字滚动和页面入场表演；
- 尊重 `prefers-reduced-motion`。

## 十一、永久反 AI 约束

以下条款适用于本轮及后续新增前端：

1. 禁止以紫蓝渐变、玻璃拟态、发光色团或渐变字作为默认品牌语言；
2. 禁止巨型 Hero、营销式欢迎页和与任务无关的文艺副标题；
3. 禁止所有信息进入同尺寸圆角卡片；
4. 禁止卡片套卡片和 Bento 式均匀格子填满复杂工具页；
5. 禁止万能胶囊、彩色徽章和小图标盒承担主要层级；
6. 禁止标题、说明、状态、技术字段和主动作获得相近权重；
7. 禁止技术 ID、哈希、JSON、英文错误码与普通用户任务平铺；
8. 禁止页面名称下面紧贴装饰性段子、口号或“释放潜能”等泛话；
9. 禁止浮空主按钮遮挡内容；
10. 禁止依靠彩色左竖线表达选择、类型、错误或警告；
11. 禁止颜色成为唯一状态信号；
12. 禁止每个页面复用“顶部标签＋左栏＋卡片主区＋右卡片栏”的同一骨架；
13. 禁止为了“更现代”隐藏熟悉操作、快捷键或显式状态；
14. 禁止用随机非对称、重叠文字、旋转卡片或装饰编号假装编辑设计；
15. 禁止把视觉趋势、生成工具输出或单张概念图直接当成生产规格。
16. 禁止用同尺寸、同留白、同边界的容器机械填满页面；视觉层级必须对应真实任务优先级，而不是对应栅格空位。
17. 普通用户层默认使用自然中文；内部 ID、JSON key、英文枚举、错误码和文件路径只能在高级信息、源码模式或确有专业必要的文件名中出现，不得与中文标签同行拼接。
18. Agent 可通过语义 DOM、`data-*`、可访问名称、结构化数据和源码读取专业字段；不得为了方便 Agent 而把英文技术字段长期平铺给普通用户。

任何新页面在合并前必须回答：它的唯一主任务是什么、主工作对象是什么、次要信息为何存在、为什么需要这个容器、用户下一步在哪里。如果回答只能是“看起来更丰富”或“保持一致”，该设计不得合并。

## 十二、选择、焦点与状态合同

### 12.1 删除范围

必须删除以下所有彩色左竖线或等价内嵌竖条：

- 当前场景；
- 编辑块类型；
- 校验 error/warning/info；
- 审计发现；
- Review warning、安全组、内容高亮、冲突严重度和自动依赖；
- 当前时间轴；
- 时间轴错误；
- 后续新增页面的选中和状态块。

纯布局分隔线不得被误删，但应使用完整边界、空白或整面背景，不与状态色条混淆。

### 12.2 替代信号

- 当前导航或当前对象：整行反白＋“当前”文字，语义使用 `aria-current`；
- 列表中的单一选中对象：整行或整块背景变化＋完整边界，语义使用 `aria-selected`；
- 人类裁决中的单选：真实 radio＋完整候选内容＋明确“已选择”文字；
- 批量多选：真实 checkbox＋已选数量，不把普通当前对象伪装成复选框；
- 键盘焦点：独立高对比 focus ring，不与当前、选中、单选或多选状态共用；
- 错误：图标＋中文错误动词＋定位信息＋完整边界；
- 警告：图标＋中文说明＋可执行下一步；
- 成功：勾选＋中文结果；
- 只读：锁符号＋“已保存/已批准/已退回，只读”文字；
- dirty：文件名或对象名旁的稳定符号＋保存状态，不靠红点独自表达。

## 十四、语义锚点与测试迁移

重构可以改变 DOM 层级，但以下原则不可违反：

- 现有 `data-*` 和 ID 若仍准确表达同一语义，优先保留；
- 若必须替换，必须在同一提交中迁移永久测试并证明行为等价；
- 不得先删除测试锚点，再用“视觉已重做”解释覆盖消失；
- 不允许测试只证明元素存在，却没有证明保存、定位、只读、预览或联动行为。

高风险锚点包括但不限于：

- `.block[data-line][data-object-ref]`；
- `#preview-view`、`.preview-frame`、`.preview-trace`；
- `#review-preview-host`；
- `[data-safe-group]`；
- `[data-source-technical]`；
- `[data-tech-details]`；
- `[data-choice-option-unit]`；
- `[data-choice-unit]`；
- `[data-choice-selected]`；
- `[data-choice-exclude]`；
- `[data-choice-regenerate]`；
- `[data-action="save-decision"]`；
- `[data-action="preview-result"]`；
- `[data-action="approve-result"]`；
- `[data-action="return-result"]`；
- `[data-decision-receipt]`；
- `[data-result-receipt]`。

### 14.1 旧视觉系统退出合同

“不复用旧视觉系统”按以下机械证据验收：

- 已迁移模式不得继续消费旧 `--bg`、`--panel*`、`--accent*`、`--gold*`、`--shadow-1`、`--shadow-2` 视觉 token；最终波结束时 Editor 生产样式中不再存在这些旧 token；
- 删除应用背景径向光团、项目/状态万能胶囊、通用面板阴影、8–10px 通用圆角卡片和所有 `inset 3px 0` / 状态 `border-left: 3px` 视觉签名；
- 保留语义准确的 `data-*`、ID 和业务类；纯视觉类如果只服务旧卡片/彩条样式，则随对应模式迁移删除，不建立永久别名层；
- 分阶段期间未迁移模式可在临时外壳内继续使用旧样式，但新旧 token 不得在同一已迁移组件中混用；
- 每波记录迁移前后真实页面截图矩阵；最终矩阵覆盖八模式、横切状态、Renderer 玩家状态和四种窗口尺寸；
- “像素不重合”不以逐像素差异百分比代替功能判断，但新页面不得保留上述旧布局拓扑、视觉签名或卡片骨架。

## 十五、中文、可访问性与窗口适配

### 15.1 中文优先

- 普通用户界面使用领域中文；
- 英文错误码、schema 字段、哈希和内部对象名进入技术详情；
- 中西混排、标点禁则、引号、括号、数字、英文 ID 和换行使用真实中文样本验证；
- 不把内部错误码直接当按钮或标题；
- 不翻译稳定技术身份本身，但必须给出中文解释。

### 15.2 可访问性

- 颜色不作为唯一信号；
- 所有交互具备可见键盘焦点；
- 保留语义化按钮、输入、表格和列表；
- 支持字体缩放；
- 普通文本对比度至少满足 WCAG 2.2 AA `4.5:1`，大文本至少 `3:1`，非文本控件与状态边界至少 `3:1`；
- 键盘焦点环至少 2px，并在相邻颜色上达到 `3:1`；
- 动效支持减少运动；
- Inspector 与 Dock 的折叠、调整尺寸和恢复具有键盘路径；
- 浏览器 200% 缩放下核心操作仍可达，文字不被裁切，内容不得只靠横向滚动读取。

### 15.3 窗口适配

Surdet 是桌面创作工具，不强求手机端完整创作。至少验证：

- 1920×1080：标准工作区；
- 1440×900：常用笔记本工作区；
- 1280×720：紧凑但功能可达；
- 1024×768：目录/Inspector/Dock 可折叠，不遮挡主工作对象。

Windows 125% 与 150% 系统缩放、浏览器 100%/125%/150%/200% 缩放纳入最终可访问性波验证。

任何尺寸下都不得出现三个独立滚动长栏同时挤压中央任务；预览舞台不得被因果轨迹压缩。

## 十六、实施分解原则

本规格是全局设计合同，后续实施计划必须拆成可独立验收的波次：

1. 视觉 token、应用框架和反 AI 永久测试；
2. 剧本主工作区；
3. 流程图与时间轴；
4. 配置；
5. 预览与因果 Dock；
6. 审阅；
7. 统计与审计；
8. Renderer 玩家界面与主题边界；
9. Host/Shell 消费回归；
10. 全模式一致性、窄窗口与可访问性收口。

每一波只修改当前前端白名单，先建立最小 RED，再完成聚焦 GREEN、类型检查、构建和真实页面检查。不得把整个重构压成一个超大提交，也不得在半完成状态 push 到主分支供用户承担整合风险。

## 十七、验证与审核

### 17.1 自动化

每个波次至少覆盖：

- 当前模式永久 DOM/交互合同；
- 选中、焦点、错误、空状态、dirty 和只读状态；
- 相关 workspace 聚焦测试；
- typecheck 与 build；
- 与变更风险相符的相邻回归；
- 跨 Editor/Renderer 或影响 Host/Shell 消费边界时才升级聚合门。

`packages/editor/test/` 整体属于本重构的既有行为保护面。实现计划可以按波次选择聚焦门，但不得删除、跳过、弱化或用纯快照替代下列关键合同：

- 项目与保存：`model-roundtrip.test.ts`、`project-io.test.ts`、`authoring-project-storage.test.ts`、`history.test.ts`、`autosave.test.ts`；
- 块编辑、流程与时间轴：`flow-edit.test.ts`、`flow-labels.test.ts`、`graph.test.ts`、`timeline-model.test.ts`、`config-edit.test.ts`；
- 资产与配置呈现：`assets.test.ts`、`presentation-asset-catalog.test.ts`、`calendar-map.test.ts`、`project-config-display.test.ts`、`terminology-import.test.ts`；

Renderer 波至少保护：`theme.test.ts`、`ui-views.test.ts`、`gamepad.test.ts`、`keybindings.test.ts`、`backlog-search-controller.test.ts`、`settings-store.test.ts`、`loading-progress.test.ts`、`legacy/nvl.test.ts`、`legacy/menu-layer.test.ts`、`legacy/presentation-controller.test.ts`、`layers/dialogue-layer.test.ts`、`layers/gallery-layer.test.ts`、`layers/system-panel-layer.test.ts`、`layers/world-layer.test.ts`、`integration/presentation-clear.test.ts`、`integration/presentation-save-roundtrip.test.ts`、`integration/renderer-runtime.test.ts`、`integration/resource-cycles.test.ts`、`api/query-purity.test.ts` 和 `api/renderer-contract.test.ts`。Host/Shell 不换皮，但相邻消费回归至少覆盖 `player-ui-coordination.test.ts`、`renderer-player-shell-slots.test.ts`、`player-experience-e2e-contract.test.ts`、`save-store.test.ts` 与 `window-state.test.ts`。

视觉 DOM 可以彻底更换，但对象身份、保存、撤销、预览、因果定位、回执只读和显式写入语义必须原样成立。若旧测试依赖被删除的纯样式类名，应先用稳定语义锚点建立等价 RED，再迁移测试；不得先删断言再宣布视觉重构通过。

### 17.2 真实页面

施工 AI 必须在真实页面中检查：

- 典型项目；
- 长标题、长中文正文和多选项；
- 空项目；
- 错误与警告；
- dirty 与保存失败；
- 审阅新建、保存中、失败、回执重开只读；
- 四种桌面窗口尺寸；
- 键盘焦点；
- 预览 Canvas 与因果 Dock。

Surdet 人工 Editor 服务使用既有 `4175` 端口；`4173` 保持不占用，避免再次干扰相邻项目。启动真实页面后必须同时核验页面标题、项目路径、监听端口与进程归属，不能只因浏览器成功打开就认定环境正确。

真实页面截图、视频、浏览器 trace 和临时视觉 artifact 必须写入仓库外的 `%TEMP%\surdet-frontend-redesign-*` 或项目所有者明确指定的临时目录；禁止暂存、提交或移动进仓库。正式文档只记录必要的文件身份、结论和可复现路径，不把整套截图矩阵变成长驻文档噪音。

自动化通过不能替代真实画面检查；真实画面好看也不能替代功能测试。

### 17.3 审核分工

- 施工 AI：本地修改、测试、精确提交、证据和真实页面检查；
- 本地独立复审：在任何 push 授权之前，只读核对提交范围、功能合同、测试和证据；
- 远端审核 AI：仅在项目所有者明确授权 push 后，直接读取 GitHub 上的真实提交或 PR，独立指出 Blocker/High/Medium/Low；
- 项目所有者：决定产品方向、不可逆操作和必要的主观视觉取舍；
- 不再要求项目所有者在两个 AI 之间转述技术事实；
- 施工 AI 不得为了获得远端审核而提前 push 半成品；未经项目所有者明确授权，不 push、不发布、不进入下一主题；
- 每个可见波次由项目所有者只做主观视觉验收，技术事实由施工 AI 与审核 AI 直接从代码和证据中读取。

每波必须分别记录：

```text
TECHNICAL_GATES = PASS | FAIL
LOCAL_INDEPENDENT_REVIEW = PASS | NEEDS_FIX
OWNER_VISUAL_ACCEPTANCE = PASS | NOT_RUN | NEEDS_FIX
REMOTE_REVIEW = PASS | NEEDS_FIX | NOT_AUTHORIZED
```

施工 AI 的截图检查只能证明“页面可运行且证据已准备”，不能代填 `OWNER_VISUAL_ACCEPTANCE=PASS`。Owner 暂不验收时可以继续修复技术问题，但不能宣称该波主观视觉已接受。

## 十八、失败与回退

- 某一模式重构失败时，停止在该模式，不扩散到下一模式；
- 不通过回退后端合同“适配”新界面；
- 不删除失败测试、截图或日志以制造绿灯；
- 不用增大 timeout、隐藏 overflow 或删减内容掩盖布局问题；
- 不用全局 `!important`、任意绝对定位或复制 DOM 绕过结构问题；
- 每波提交必须可单独回滚；
- 未完成模式通过临时兼容外壳运行，不能复制业务逻辑；
- 任何数据丢失、回执身份变化、存档变化或真实项目 mutation 都是立即停止条件。

## 十九、否决方案

### 19.1 只重写一份 CSS

无法覆盖命令式 DOM、内联 SVG 颜色、页面拓扑和 Renderer 玩家界面，不算全前端重构。

### 19.2 所有页面使用同一套版本案卷表格

会让创作、流程、时间轴和预览都退化为档案系统，与“创作优先”冲突。

### 19.3 同时保留旧版与新版主题切换

会形成长期双维护，没有当前产品价值，拒绝。

### 19.4 用组件库默认主题快速替换

会再次得到可互换的 AI/SaaS 模板，并可能引入新依赖，拒绝。

### 19.5 为视觉统一修改后端输出

会扩大为跨层合同工程，违反纯前端边界，拒绝。

### 19.6 一次性重写全部 DOM

会同时打碎测试、状态联动、快捷键和审阅语义，无法安全定位回归，拒绝。

## 二十、成功标准

只有同时满足以下条件，才能声明全前端重构完成：

- [ ] 八个 Editor 主模式全部迁移到新应用框架；
- [ ] Renderer 视觉与主题边界完成收口，Host/Shell 消费回归通过；
- [ ] 所有彩色左竖线已删除；
- [ ] 不再存在卡片海、渐变玻璃、浮空主动作和装饰性废话；
- [ ] 每个模式拥有独立、任务匹配的主工作面；
- [ ] 加载真实项目后的剧本创作工作面达到成熟桌面工具的信息密度和层级：目录、稿件、上下文/预览与底部 Dock 围绕同一场景协同，中央稿件仍是最大区域；
- [ ] 任何同屏预览、时间轴或因果 peek 均复用既有状态、回调与单一运行时，没有第二个 iframe、trace 或 timeline edit 真相；
- [ ] 最终视觉验收使用含真实内容的 Starter/隔离 fixture，不以空项目壳层截图冒充全前端完成；
- [ ] 创作页默认不暴露版本、指纹和来源噪音；
- [ ] 审阅和审计仍能完整读取技术事实；
- [ ] 所有现有功能合同通过；
- [ ] 中文长文本、空状态、错误、dirty、只读和窄窗口均经过验证；
- [ ] 选中、焦点和状态不依赖单一颜色；
- [ ] 预览舞台居中、不拉伸且不被轨迹挤压；
- [ ] 每个可见波次的 `OWNER_VISUAL_ACCEPTANCE=PASS` 由项目所有者亲自给出，未验收波次不冒充主观通过；
