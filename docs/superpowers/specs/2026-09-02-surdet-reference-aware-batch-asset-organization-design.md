# Surdet 引用感知批量素材整理设计

## 1. 目标

让用户在素材中心一次选择多个同类素材，把它们移动到已有目录或逐项修改文件名；Surdet 必须先展示整批影响，再以一次不可拆分的操作同时更新物理文件和全部可可靠识别的静态引用。

本阶段解决的是成熟素材库最常见的整理工作：项目积累一段时间后，用户需要把散落素材归档、成组改名，或交换两个已占用名称。它不是“循环调用多次单素材整理”。只要逐项提交，就会出现前半批成功、后半批失败、引用先后替换互相污染，以及 A→B、B→A 无法安全完成等问题。

## 2. 方案选择

采用“一个批次、一个计划、一个 journal、一个回执、一次撤销”的方案。这里的原子性是可恢复、不可部分确认的逻辑事务，不声称多个文件在操作系统层面同一瞬间变化。

备选方案：

1. **逐个调用现有单素材整理。** 实现快，但会产生部分成功，无法可靠交换路径，连续引用替换也会把 A→B 后的结果再次当作 B→C 输入。拒绝。
2. **整批原子整理。** 共享规划器一次读取项目并计算所有映射；CLI 先备份全部源素材，再发布全部目标，最后一次性改写文本；任一失败回退整批。采用。
3. **通用目录规则、模板和自动归档平台。** 长期可能有价值，但当前没有足够真实规则和调用方，会把明确功能扩张成平台。暂不实现。

## 3. 产品范围

### 3.1 包含

- 一次选择 2 至 100 个同类物理素材；
- 背景、立绘或头像三类，单批只允许一种类别；
- 共同目标目录，并可在“逐项调整”中修改每项最终文件名；
- 移动链、路径交换和闭环，例如 A→B、B→A；
- 对所有已支持静态引用做一次同步改写；
- 整批阻断、提交、恢复、回执和撤销；
- 列表跨筛选保留选择，切换项目时清空；
- 中文、键盘可操作、桌面与 800 像素窄窗口可读。

### 3.2 不包含

- 混合素材类别、改变扩展名、转码、覆盖外部文件、删除或自动去重；
- 自动创建目录、移动整个目录、按规则递归整理；
- 音乐、环境音、音效、语音、视频、字体与 other；
- 猜测动态脚本、插件私有格式或自由文本引用；
- 标签、收藏、智能分类、自动命名模板或素材规则引擎；
- 新 daemon、数据库、素材索引、项目锁或通用事务平台；
- 下一轮前端整体重构或 Wave 7。

## 4. 批次合同

### 4.1 请求

一个批次由稳定排序的 `moves[]` 构成，每项至少包含：

- `sourcePath`：当前规范项目相对路径；
- `targetPath`：目标规范项目相对路径。

规划器为每项从规范 source/target 派生稳定的 `moveId`，并按规范化后的 `sourcePath` 排序。相同输入无论 UI 选择顺序如何，都产生相同计划和指纹，不接受调用方另造会漂移的展示编号。

每个源路径只能出现一次，每个目标路径只能出现一次。路径判重先做 NFC 规范化，再使用现有跨平台大小写折叠顺序；不能只在当前 Windows 文件系统上碰撞时才发现。源与目标必须属于同一批次类别、扩展名不变、目标目录真实存在且安全。任一项无变化时整批阻断，避免在结果中混入假动作。

### 4.2 目标占用

- 目标被批次外文件占用：阻断；
- 目标正好是同批另一项的源路径：允许；
- 两项指向同一个目标：阻断；
- Windows 大小写折叠后的重复同样视为冲突。

因此移动链和交换成立：先把全部源文件移入各自受控备份，再从备份发布所有目标，不依赖操作顺序腾空路径，也不需要引入通用图执行器。

### 4.3 语义键与立绘组

- 背景与头像沿用单素材阶段的唯一语义键规则；
- 物理目录变化但语义键不变时，只移动文件，不制造无意义引用改写；
- 语义键发生变化时，新键不能与批次外素材冲突；
- 批次内旧键到新键的交换允许，但映射必须一一对应；
- 同一旧语义键对应多个物理文件时，语义重命名仍阻断；仅目录迁移且语义键不变、物理路径都唯一时可放行。

立绘 `角色_服装_表情` 组采用完整性规则：

- 单个成员改变角色或服装，且项目存在同组其他表情时，继续阻断；
- 只有批次包含该语义组全部物理成员，并把它们一致映射到同一个新角色/服装、同时保持各表情唯一时，才允许组级重命名；
- 裸角色引用只有在该角色全部已知立绘都被一致映射时才改写；否则整批阻断；
- 组内任一成员遗漏、目标冲突或映射不一致，整批阻断并指出缺少的成员。

## 5. 引用改写

继续使用单素材阶段已经验证的静态引用合同：背景场景与时间轴、鉴赏配置；立绘场景与时间轴；头像角色配置。

批量规划不能顺序套用单项替换。每个项目文本只解析一次，所有替换都基于原始内容和一张不可变映射表完成：

- `A → B, B → C` 时，原始 A 变 B，原始 B 变 C；A 的结果不会再次变 C；
- `A ↔ B` 时，两个原始键正确交换；
- 同一字段若被两条映射同时主张，整批阻断；
- 同一物理引用只生成一条稳定的 reference change。

所有参与扫描的场景、时间轴、配置与受支持项目文本都纳入同一计划基线。任一不透明引用、扫描不完整或无法归属到唯一源素材的动态引用，都阻断整批。UI 必须标明受影响的素材项和文件，不能只显示抽象错误码。

## 6. 计划投影

公开计划包含：

- operationId、planId、planFingerprint、projectRevision 与整体状态；
- 规范化、稳定排序的 `moves[]`，每项投影旧/新路径与旧/新素材语义；
- affectedAssetCount、affectedReferenceCount、affectedFileCount；
- referenceChanges，每条带排序后的 `moveIds` 或受影响源路径；
- blockers，可关联排序后的一个或多个 `moveIds`/源路径；
- 是否包含链或交换，仅作为人类摘要，不改变执行语义。

计划指纹包含完整移动图、素材清单基线、所有扫描文件身份、引用改写与阻断结果。提交时只接受同一批次的原计划指纹。任一 blocker 存在时内部 `textChanges` 必须为空，不得留下可被误提交的部分准备结果。

## 7. 原子写入与恢复

继续使用现有素材 authority、项目身份、项目 lease、写入 gate、recovery barrier 和 `.surdet/asset-relocation/<operationId>` 工作区。单素材整理作为长度为 1 的批次走同一实现，不保留第二套生产状态机。

一次提交顺序：

1. 核对整批源、目标目录、批次外目标占用、素材清单和所有扫描文本；
2. 准备所有新文本和旧文本备份；
3. 写入一个待提交 journal；
4. 按稳定索引把全部源文件移动到各自独立备份；
5. 从各备份独占发布全部目标；
6. 原子替换全部文本；
7. 回读全部目标和文本；
8. 写入一个整批回执。

journal 对每项二进制移动保存独立状态、备份位置和结果身份，对每个文本保存独立替换状态，但操作状态只有一个。不能把部分项投影成成功回执。

普通失败时按逆序回退整批：撤掉仍属于本操作的已发布目标，把备份恢复到全部原路径，再恢复文本。任何路径出现外部变化时停止自动覆盖并进入现有人工恢复阻断。

重启恢复继续或回退整个批次。撤销前一次性核对所有目标与文本仍匹配回执；核对通过后才开始反向事务。任一项已被编辑时，整批撤销拒绝，不做部分撤销。

## 8. 存储与兼容边界

本项目仍处于内部开发阶段，旧 relocation 操作不是公开存档格式。本阶段把现有内部 relocation 记录升级为批次形状，并让单素材请求由客户端发送一个元素的 `moves[]`。不建立迁移平台或长期双协议。

为避免升级当天遗留未终结操作被误写，authority 启动时若发现旧 schema 的非终结记录，必须保持 recovery barrier 并给出明确人工处理提示；旧的已完成记录可继续以只读历史摘要显示，不能重新提交。新写入一律使用批次 schema。

## 9. Editor 交互

### 9.1 选择模式

素材中心保留普通单选浏览。用户点“批量整理”进入选择模式后：

- 物理素材行改为普通行容器，内含标准复选框与独立的“查看详情”按钮；禁止在现有 `button[role=option]` 内嵌复选框，避免交互嵌套和无效 ARIA；
- 第一次选择锁定本批素材类别，其他类别只读并说明“一个批次只能整理同类素材”；
- 筛选、搜索和切换目录不丢失已选项；
- 页内固定标题行显示“已选 N 项”“整理所选”“退出选择”，不是贴底悬浮条；
- 切换项目、重新载入项目或退出选择时清空批次。

### 9.2 批量工作台

点击“整理所选”进入同页工作台：

- 顶部说明本批类别和数量；
- “统一放到”选择已有同类目录；
- 默认保留每个原文件名；
- “逐项调整”是普通可折叠表格，每行显示当前位置、目标目录、最终文件名和就地错误；
- 不使用卡片墙、彩色左竖线、状态胶囊墙、渐变、玻璃或浮动确认按钮；
- 主按钮是页面文档流底部的“检查整批影响”。

### 9.3 影响与结果

预览先给一句摘要，例如“将整理 12 个素材，更新 31 处引用，涉及 8 个项目文件”。其后按素材和来源类型展开明细。交换路径用自然中文说明，不暴露内部备份步骤。

阻断时把共同问题放在顶部，逐项问题贴近对应行；不显示提交按钮。可执行时页面底部显示“整理 12 个素材并更新 31 处引用”。

成功后显示新位置摘要、引用数量、“查看整理结果”和“撤销整批整理”。重开回执仍能读取完整批次。恢复状态以同一工作台展示，不另造管理后台。

800 像素宽时，目录与文件名输入纵向排列，逐项表格转换为有明确字段名的行块；页面不得横向溢出。

## 10. Editor 状态边界

- 未保存场景、时间轴、配置或其他项目写入存在时，不允许开始规划；
- 从检查影响到提交/取消/恢复结束，共用现有 `asset-relocation` 页面写入冻结；
- 修改任一目标后旧计划立即作废；
- 提交成功后完整重读当前项目，选择新路径集合，并保留素材中心当前位置；
- 单素材详情入口继续存在，但调用相同批次能力；
- 执行期间统一使用 `aria-busy` 和 `aria-live`，锁定选择、规则、导航、导入与引用跳转；重渲染后恢复合理焦点；
- 主界面尽量使用中文；内部路径、素材键和技术详情只在必要位置或可展开详情中出现。

## 11. 错误语义

用户至少能区分：

- 批次含不同素材类别；
- 源素材缺失、重复选择或已变化；
- 多项指向同一目标；
- 目标被批次外文件占用；
- 立绘组未完整选择或映射不一致；
- 新素材键与批次外素材冲突；
- 存在无法自动改写的引用；
- 项目在计划后变化，需要重新检查；
- 上次批量整理需要恢复；
- 批次结果已被后续编辑，不能自动撤销。

## 12. 验证

- Authoring：稳定排序、重复源/目标、外部目标占用、链、交换、同时引用替换、立绘全组与缺员阻断、不透明引用；
- CLI：一次计划、整批提交、源全部先备份、普通失败整批回退、重启恢复、回执重开、整批撤销和外部变化拒绝；
- HTTP/client：严格 `moves[]`、绑定、公开投影和不泄露绝对路径；
- Editor：跨筛选选择、同类锁定、统一目标、逐项调整、计划失效、阻断、回执与恢复；
- 一条真实浏览器路径：选择两个被引用背景，交换名称，预览、提交、重载后场景仍正确，再撤销；
- 受影响工作区各运行一次聚焦测试、类型检查和构建；普通推送后观察一次远端 CI。

## 13. 完成标准

1. 用户可在素材中心选择多个同类素材并一次检查整批影响；
2. 链和路径交换不会被目标占用误判，也不会发生顺序替换污染；
3. 任一失败不会留下部分移动或部分引用更新；
4. 立绘组、不透明引用和批次外冲突不会被猜测处理；
5. 一个回执可重开并安全撤销整批；
6. 单素材整理继续通过同一实现工作；
7. UI 中文、克制、层级清楚，桌面和窄窗口可用；
8. 没有新增第二套锁、索引、服务或通用事务平台；
9. 规格、任务书、实现、聚焦验证、真实浏览器检查、普通提交、普通推送和远端 CI 全部完成后，只在长期台账追加一段简短结论。
