# Surdet 场景路径安全生命周期设计规格

日期：2026-09-02
状态：已批准施工
范围：Editor 场景目录、流程图场景操作与项目保存

## 1. 目标

关闭一个真实的数据边界：从 `content/scenario` 子目录读取的场景，在重命名或删除后必须继续使用它的真实相对路径；保存成功并重开项目后，不得在根目录生成同名副本，也不得让旧文件从子目录重新出现。

本轮同时让这两项已有操作可从场景目录发现并使用键盘完成。流程图右键入口继续保留，但当同一运行时场景 ID 对应多个物理文件时必须拒绝猜测目标，并引导用户去场景目录选择精确文件。

## 2. 已确认的问题

- 项目加载会递归读取 `content/scenario/**/*.gal`，Map key 与 `SceneEntry.file` 保留相对目录。
- 现有重命名把子目录场景的句柄清空，却在保存时固定向 `content/scenario/<id>.gal` 写入，因此会丢失原目录。
- 现有删除只会立即删除根目录文件；子目录文件只从内存移除，重开项目后会再次出现。
- 现有流程图按 `sceneId` 反查第一个场景；同 ID 位于不同目录时可能操作错误文件。
- 删除当前立即改磁盘，和“保存全部”不是同一用户提交边界，也没有可靠的待保存状态。

## 3. 产品决定

### 3.1 路径是场景文件身份的一部分

Editor 继续以现有 `state.scenes` Map key 和 `SceneEntry.file` 表示物理位置。运行时 `sceneId` 仍是剧情引用语义，但不能单独用于选择要改名或删除的磁盘文件。

### 3.2 重命名与删除先进入待保存状态

- 重命名只更新内存场景、声明和引用，并登记旧文件的精确相对路径；不立即删除磁盘旧文件。
- 保存时先把新文件完整写入原目录，再删除旧文件。
- 新文件写入失败时绝不删除旧文件。
- 旧文件删除失败时保留待处理记录，项目仍显示“未保存”，允许下一次保存重试；不得把部分完成伪装成成功。
- 删除现有场景时先从当前工作集移除并登记精确文件路径；真正删除发生在“保存全部”。
- 尚未落盘的新场景可直接从内存移除，不制造磁盘删除记录。

### 3.3 限制复杂操作链

同一场景存在尚未保存的重命名时，禁止再次重命名或删除，并用中文提示先保存。这样避免在一轮内建立多段路径迁移或恢复系统；当前真实需求只需要可靠的一步改名。

### 3.4 可发现的场景目录操作

每个场景目录行保留原选择按钮，并新增克制的“重命名”“删除”动作。动作必须是原生按钮、可 Tab 到达、具备清楚的可访问名称；不得用彩色竖线、悬浮菜单或仅 hover 可用图标表达。

流程图继续复用同一实现。若 `sceneId` 唯一，右键操作精确落到该 Map key；若不唯一，停止并提示从场景目录选择，不得选择第一项。场景目录可以按精确路径删除重复项；由于剧情引用只保存 `sceneId`，重复 ID 状态下的重命名仍须拒绝，避免把含糊引用批量改错。

## 4. 数据与失败不变量

1. `SceneEntry.file` 始终是 `content/scenario` 下的安全相对 `.gal` 路径。
2. 任何绝对路径、空片段、`.`、`..` 或越级路径在写入/删除前失败。
3. 待删除记录只引用当前项目加载时取得的精确场景路径，不接受用户任意路径输入。
4. 重命名保存顺序固定为“写新文件 → 删除旧文件”。
5. 写新文件失败：旧文件存在、待删除记录存在、场景保持 dirty。
6. 删除旧文件失败：新文件可以存在，但待删除记录和未保存状态必须保留。
7. 普通项目切换和演示项目加载会清空上一项目的待删除记录。
8. `beforeunload`、项目栏保存状态与素材整理前置检查都必须把场景待删除视为未保存。
9. 场景仍作为项目入口或由事件、成长、日历配置引用时，重命名和删除必须先拒绝并引导用户修改配置；不得留下已知悬空配置。
10. Windows 下场景物理路径按大小写不敏感比较；只改文件名大小写、复用待删路径或覆盖现有目标均须拒绝。
11. 保存、重命名与删除共享串行写入边界；切换项目不得静默丢弃待保存的场景操作。
12. 本轮不改变 `.gal` 语法、运行时场景 ID、项目格式、Core/Renderer/CLI 或素材 authority。

## 5. 明确不做

- 不建立通用文件事务、journal、manifest、哈希证据或恢复平台。
- 不扩展现有自动备份格式来恢复尚未保存的改名/删除意图；保存前旧磁盘文件保持不动，并由离开页面与项目切换保护阻止静默丢弃。
- 不支持跨目录移动场景；重命名保持原目录。
- 不允许同一场景连续多次未保存重命名。
- 不重做新建场景表单、流程图布局、预览或配置入口。
- 不删除真实用户项目文件作为测试；所有文件操作只使用内存句柄夹具。

## 6. 验收标准

- 根目录与嵌套目录场景重命名后，新文件位于原目录，旧文件在新文件成功写入后才删除。
- 新文件写入失败时旧文件保持不动；旧文件删除失败时待保存状态保持。
- 嵌套场景删除经“保存全部”删除精确旧路径，重开所需的磁盘事实不再残留。
- 同 ID 多路径时，流程图操作拒绝猜测；场景目录仍能对精确路径操作。
- 目录操作可由鼠标和键盘使用，当前选择行为不回归。
- 最相关的 Editor 测试、typecheck、build 和一次隔离项目保存/重读检查通过。
