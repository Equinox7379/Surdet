# Surdet 引用感知素材整理设计

## 1. 目标

让用户在素材中心把一个真实素材移动到同类目录，或修改它的文件名；Surdet 必须先展示影响，再在用户确认后同时更新物理文件和所有能够可靠识别的静态引用。

这不是文件管理器的简单“重命名”。一个背景、立绘、头像、音乐或视频可能被场景、时间轴、角色配置和鉴赏配置共同引用。任何只改文件名、不改引用的实现都会制造损坏项目，因此本阶段以“完整、可解释、可撤销的一次整理”为产品单位。

## 2. 产品决定

采用“素材详情内联整理 + 现有本机素材权限通道”的方案：

- 用户从素材中心选中单个物理素材，在固定详情区进入“移动或重命名”；
- Editor 只收集目标目录和最终文件名，不直接写项目；
- Authoring 共享层负责识别新旧素材语义、计算引用改写和阻断项；
- CLI 在现有素材权限服务内执行计划、重新核对、提交、回执和撤销，共用现有项目身份、浏览器绑定和项目占用锁；
- 提交成功后 Editor 重新读取当前项目，并把选择切换到新路径。

不采用以下方案：

1. **浏览器直接调用 File System Access 改名。** 无法保证物理文件与多个文本引用一起成功，也无法可靠恢复中途失败。
2. **把 Authoring 的文本 change 系统立即扩展成通用二进制事务平台。** 长期概念整齐，但会同时扩大 Agent、CLI、Editor 和恢复协议，超过当前单项整理的真实需要。
3. **列表行内编辑或拖入目录。** 列表行本身是单选按钮，继续塞操作会破坏键盘语义；拖动也无法自然承载引用影响确认。可在本闭环稳定后再独立考虑拖动快捷方式。

## 3. 范围

### 3.1 包含

- 单个、真实存在且身份唯一的 `content/assets/**` 文件；
- 在同一素材类别的已有目录之间移动；
- 修改文件名，但保留原扩展名；
- 背景、立绘和头像三类素材的物理整理；
- 对已支持的静态引用生成影响预览并同步改写；
- 目标冲突、路径不安全、跨类别、无效立绘名、重复素材键和无法可靠更新的引用显式阻断；
- 提交前重新核对源文件、目标位置、相关文本和计划身份；
- 成功回执与一次显式撤销；
- 自然中文界面、键盘操作和窄窗口可读性。

### 3.2 不包含

- 批量选择、批量移动或批量重命名；
- 改变扩展名、转码、压缩、覆盖、合并或自动去重；
- 跨素材类别移动；
- 移动整个目录或自动创建任意新目录；
- 猜测脚本变量、插件、自定义指令或自由文本中的动态路径；
- 修改素材内容；
- 改变项目格式、游戏运行时或 Agent Port 公共能力；
- 用本阶段顺手实现删除素材、标签、收藏、搜索索引平台或批处理工作流；
- 自动整理音乐、环境音、音效、语音、视频、字体和 `other`。这些类别当前缺少覆盖所有运行入口的统一引用合同，留给后续独立增量；
- 启动下一轮前端重构或其他 Wave。

## 4. 可安全改写的引用

共享规划器只改写当前 Surdet 已经有明确语义合同的引用：

| 素材类型 | 来源 | 改写位置 |
| --- | --- | --- |
| 背景 | 场景 | `@bg` 第一个参数 |
| 背景 | 时间轴 | background track 的 `cue.key` |
| 背景 | 鉴赏配置 | `content/config/gallery.json` 的 `cgs[].src` |
| 立绘 | 场景 | `@show` 的角色服装键与表情参数 |
| 立绘 | 场景 | `@hide`、`@mov` 的完整角色服装键 |
| 立绘 | 时间轴 | portrait track 的 `target` 与 cue 的 `expression` |
| 头像 | 角色配置 | `game.config.json` 的 `characters.*.avatar` |

`@unlock_cg` 引用的是鉴赏条目 ID，不随背景素材改名；规划器只改写对应鉴赏条目显式、非空的 `src`，解锁指令保持不变。若 `cgs[].src` 省略而运行时会以 `cgs[].id` 作为背景键，且该 `id` 命中旧背景键，本轮必须作为不透明 fallback 引用阻断，不能改写稳定的鉴赏条目 ID，也不能静默放行。音乐、环境音、音效、语音、视频、字体和 `other` 即使当前素材智能能显示部分静态引用，也不在第一版自动写入范围内，因为时间轴、字体配置和自定义入口尚未形成完整统一合同。

规划输入除了普通 `ProjectSnapshot`，还必须显式携带 `content/config/gallery.json` 的原始文本与文件身份。不能只传已经解析的只读 `galleryInput`，也不能假设 gallery 已包含在共享快照中。

场景运行时允许 `@show lynn` 省略服装和表情，语义等价于 `@show lynn:normal normal`。共享素材智能和 relocation 规划器必须使用同一默认规则识别它；重命名对应立绘时输出明确的新 `role:outfit` 与 expression，不能漏掉裸角色形式。只省略表情时同样按 `normal` 匹配。

`@hide` 与 `@mov` 也会消费立绘身份。完整的 `role:outfit` 与旧立绘键相同时必须同步改写；裸 `role` 代表该角色的一组立绘，若本次重命名改变 role，则语义含糊并阻断，不能把组操作擅自缩成单文件操作。portrait 时间轴的 `target` 对 show/expression/move/hide 全部 cue 都有效，不能只在 show/expression cue 存在时才识别；裸 role target 遇到 role 改名使用同一阻断规则。

`title_bg` 是 Renderer 标题页在未显式提供 `backgroundKey` 时使用的保留背景键。第一版允许把该文件移动到同类子目录（语义键不变），但禁止把它重命名为新的语义键；项目源码中显式写死的其他背景键由不透明项目代码扫描阻断。

## 5. 命名与路径规则

- 源路径与目标路径都必须是规范项目相对路径，位于 `content/assets/`；
- 目标目录必须已经存在，并与源文件解析为相同 `ProjectAssetKind`；
- 文件名必须是安全的单个名称，不含路径分隔符、控制字符、尾随空格、`.` 或 `..`；
- 扩展名按大小写折叠后必须与源文件一致；
- 目标路径与源路径相同时为无操作，不能提交；
- Windows 风格大小写折叠后，目标不能与另一个文件冲突；
- 新语义键不能与另一物理文件重复；
- 立绘名称必须保持 `角色_服装_表情.扩展名` 三段结构；它的语义键和表情分别来自这三段；
- 不覆盖任何既有文件，也不把冲突自动改成带数字后缀的名称。

## 6. 不透明引用防线

不能只根据“已识别引用数量”假设项目安全。规划器还要检查本轮读取的场景、时间轴和配置文本：

- 已知指令或字段中的旧键由结构化改写负责；
- 未知指令参数、未知 JSON 字段、项目 `src`、`scripts`、`test`、`tests` 下受支持的代码/JSON 字符串或其他受支持项目文本若出现精确旧语义键、旧规范项目路径或旧文件名，列为不透明引用并阻断；这包括项目自带的素材校验脚本。扫描排除依赖、构建产物和 `.surdet` 内部工作区；
- 普通台词中恰好出现同名文字不作为路径引用；
- 只匹配完整字符串值或完整指令参数，不做模糊子串替换；
- 动态拼接、插件私有格式和二进制内容不猜测、不改写。

这一策略宁可要求用户暂时手工处理一个含糊引用，也不能静默留下断链。

## 7. 人类交互

### 7.1 入口

选中物理素材后，右侧固定详情区在“引用位置”下方显示“整理素材”。缺失引用的合成条目、同键重复且无法唯一确认的条目、当前项目有未保存修改或本机权限服务未绑定时，入口不可执行，并给出中文原因。

素材列表行继续只负责选择，不嵌套编辑按钮。

### 7.2 编辑目标

展开后显示：

- 当前位置（只读）；
- “放到”——同类现有目录下拉列表；
- “文件名”——不含目录的最终名称，扩展名可见但不可改变；
- 一行实时摘要：`当前路径 → 目标路径`；
- 主按钮“检查影响”，次按钮“取消”。

### 7.3 影响预览

检查阶段不写项目。结果按层级展示：

- 将移动或重命名的文件；
- 将更新多少处引用、涉及多少个项目文件；
- 按场景、时间轴、角色配置和鉴赏配置分组的可展开明细；
- 任何阻断项及可以理解的处理建议。

只有计划为可执行时才显示“移动并更新 N 处引用”。按钮文案必须说明实际动作，不使用含糊的“确认”或“继续”。

### 7.4 执行与结果

执行时锁定输入和离开操作。成功后显示：

- 新位置；
- 已更新的引用数与文件数；
- “查看新位置”；
- “撤销本次整理”。

撤销前同样重新核对新文件和改写后的文本没有再次变化。若之后已被用户编辑，撤销必须拒绝并说明原因，不能覆盖新工作。

## 8. 权限与写入架构

本能力扩展现有 `asset-import-authority` 运行时，而不是启动第二个本机写入服务：

- 继续使用当前页面注入的 authority token；
- 继续使用当前项目绑定 challenge 与 binding token；
- 继续使用同一个项目身份和项目占用锁；
- 新增独立的 relocation 路由、类型、记录和工作区，避免把导入状态机硬改成同时表示两种业务；
- Editor 客户端只接收安全的项目相对路径、中文错误投影、公开计划和回执，不接收绝对路径或内部恢复目录。

公开投影采用明确而有限的合同：

- `RelocationPlan`：operationId、planId、planFingerprint、source、target、旧/新素材语义、状态、affectedReferenceCount、affectedFileCount、按来源分组的 referenceChanges、blockers；
- `RelocationOperationSummary`：operationId、status、sourcePath、targetPath、updatedAt、manualRecoveryRequired；
- `RelocationReceipt`：receiptId、operationId、planId、项目身份、source、target、旧/新素材语义、改写文件及提交后身份、完成时间；
- `RelocationUndoReceipt`：operationId、恢复后的 sourcePath、已恢复文本文件、撤销时间；
- 绑定快照与操作发现同时列出未终结 relocation 和最近 relocation 回执，恢复屏障同时覆盖 import 与 relocation；存在未终结写入时不得开始另一种素材写操作。

同一运行时必须提供一个统一素材写入 gate：import 的 create/upload/plan/seal/commit/cancel/undo、relocation 的 plan/commit/cancel/undo、绑定确认和启动发现等全部会改变素材 authority 状态的入口，都先检查 import 与 relocation 两类 pending/recovery 状态。恢复入口可以用于清理已经存在的操作，但同样必须发现两类 pending/recovery。不能让两个 authority 各自只看自己的操作列表。

独立 relocation 记录不是流程装饰。一次操作会同时改变一个二进制文件和多个文本文件；进程在中间退出时，如果没有最小 journal，就可能留下“文件已移动但引用未更新”或相反的损坏项目。实现只保留恢复这一真实风险所需的状态，不建立通用事务平台。

## 9. 提交不变量

在真正写入前必须再次满足：

1. 项目根身份仍与绑定一致；
2. 项目占用锁仍由本运行时持有；
3. 源文件仍是计划时的同一文件且内容未变化；
4. 目标路径仍不存在；
5. 本次不透明引用扫描涉及的全部场景、时间轴和配置文本（包括不会改写的文件与 gallery 原文）仍与计划时内容一致，并重新扫描后没有新增阻断引用；
6. 目标路径、素材类别、扩展名和新语义键仍合法；
7. 计划指纹与提交请求一致；
8. 当前不存在必须先恢复的 relocation 操作。

同一 Editor 页面也必须服从写入冻结：从开始生成可提交计划到操作结束期间，顶栏“保存全部”、配置保存、时间轴写盘、导入提交和其他会写项目的入口都不可执行，并显示“素材整理进行中”。项目占用锁负责阻止其他进程；Editor 写入冻结负责阻止本页面自己的 File System Access 写入。两者缺一不可。

任一条件不满足都停止在写入前，返回“项目已变化，请重新检查影响”。

## 10. 写入与恢复顺序

实现使用项目内 `.surdet/asset-relocation/<operationId>` 作为同卷临时工作区：

1. 把所有新文本写入 prepared，并完成关闭与落盘；
2. 记录待提交 journal；
3. 把源素材移动到受控备份位置；
4. 把备份素材移动到目标位置；
5. 逐个原子替换文本文件，并保留原文本用于回退和撤销；
6. 再次读取目标与文本，确认结果；
7. 写入完成回执。

relocation 专用 journal 必须足以在没有进程内记忆时恢复，至少持久化：

- source、受控备份和 target 的规范相对路径，以及每个已存在文件的 inode/大小/mtime/content identity；
- 每个扫描文本的旧内容身份；
- 每个待改文本的旧内容持久副本、新内容身份、prepared 路径和当前替换状态；
- 素材移动、每个文本替换和回退步骤的 intent/完成状态；
- 本操作创建或占用的每个路径，恢复时不得覆盖不属于本操作的外部新文件。

写入前的整体验证不是唯一检查点。source → backup 与 backup → target 的每一步二进制移动前，都要重新核对 source/backup/target 的预期存在状态和文件身份；目标发布必须使用不会覆盖既有路径的独占语义，任何竞争都进入恢复阻断。每个文本替换前也要再次比较它仍匹配旧内容身份；每个回退步骤只允许覆盖仍匹配本操作输出身份的文件。发现外部修改时立即停止并进入恢复阻断，不能为了继续或回滚而覆盖用户或其他进程的新内容。

若普通错误发生在进程仍存活时，先按 journal 回退到旧路径和旧文本。若进程退出，下一次 authority 启动时统一发现 import 与 relocation 两类未终结操作，并先建立共同恢复屏障；只恢复这类未终结 relocation：能完成就完成，不能证明安全就保持阻断并给出人工恢复状态。不得把不确定状态伪装成成功，也不得在 relocation 未恢复时允许新的 import，反之亦然。

撤销是完成后的反向事务：先核对所有完成后内容，再把目标移回源路径并恢复旧文本；若任何内容已变化则拒绝自动撤销。

## 11. Editor 状态边界

- 有未保存场景、时间轴或待删除/恢复项时，不允许开始整理；
- 规划期间切换项目或选择另一个素材，旧结果作废；
- 完成后通过一个明确的“重新载入当前目录”入口重新读取 game config、gallery、全部场景、全部时间轴和素材；现有仅重扫素材的 `refreshProjectAssetIntelligence()` 不足以完成这个动作；
- 重新载入时清除不再可靠的编辑历史，但不再次弹出目录选择器；
- 回到素材中心并选中新 `file:<targetPath>`；
- 标题文案由“本页不会改动任何素材”改为“整理素材会先显示影响，确认后才执行”；
- 主界面保持中文，不新增彩色左竖线、状态胶囊墙、悬浮按钮、渐变或玻璃效果。

## 12. 错误语义

对用户至少区分：

- 当前项目未绑定或目录不一致；
- 项目正在被其他写操作占用；
- 源素材不存在或已变化；
- 目标位置已有文件；
- 名称、目录、类别或扩展名不允许；
- 新素材键会与已有素材冲突；
- 存在无法自动改写的引用；
- 计划已过期，需要重新检查；
- 上一次整理需要恢复；
- 完成后的内容已变化，不能自动撤销。

技术代码只放在可展开详情中，主文案必须说明用户下一步能做什么。

## 13. 验证

- Authoring 聚焦测试覆盖每种已支持引用、立绘双字段、换行风格、引号、不透明引用和阻断条件；
- CLI 聚焦测试覆盖计划重核、目标冲突、成功提交、普通失败回退、启动恢复与内容变化后拒绝撤销；
- HTTP/client 测试覆盖绑定、严格请求、公开错误和不泄露绝对路径；
- Editor 测试覆盖详情入口、未保存阻断、目标编辑、影响预览、执行回执和撤销；
- 一条真实浏览器路径覆盖“选择被引用背景 → 改名 → 预览影响 → 提交 → 场景仍可预览 → 撤销”；
- 运行受影响工作区的类型检查和构建；
- 不重复全仓库门禁，普通推送后使用一次远端 CI 做全仓库回归。

## 14. 完成标准

1. 用户能从素材详情移动或重命名一个物理素材；
2. 写入前能看懂将改变什么，阻断时能看懂为什么；
3. 所有已支持静态引用随素材语义一起更新；
4. 动态或不透明引用不会被猜测修改，也不会静默放行；
5. 文件与文本不会在普通失败或重启恢复后停在互相矛盾的状态；
6. 成功结果可回读，未被后续编辑时可撤销；
7. 当前项目未保存内容不会被覆盖；
8. 没有新增第二套项目身份、锁、素材索引或通用事务平台；
9. UI 保持克制、中文、可键盘操作，并延续现有素材中心层级；
10. 规格、任务书、实现、聚焦验证、普通提交、普通推送与远端 CI 完成后，现有长期台账只追加一段简短结论。
