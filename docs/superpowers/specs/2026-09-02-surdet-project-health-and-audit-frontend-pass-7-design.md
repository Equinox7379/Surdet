# Surdet 项目概览与文字审计 Frontend Pass 7 设计规格

## 1. 定位

Frontend Pass 7 只重构 Editor 的“统计”和“审计”两个现有页面。它是 Post-Wave-6 / Pre-Wave-7 的前端收口，不是主线 Wave 7，也不新增引擎、Authoring、CLI 或存档能力。

本轮目标不是制造一张通用后台仪表盘，而是把两处剩余旧页面改成成熟创作工具里的“项目体检”工作区：统计页帮助人快速理解内容规模，审计页帮助人找到并处理文字一致性问题。两页保留各自导航和数据真相，只共享一套视觉语法。

## 2. 已确认问题

### 2.1 统计页

- 七张同权重 KPI 卡片形成卡片墙，阴影、圆角和悬浮位移让页面更像通用管理后台；
- 空项目显示一排零值，没有说明下一步；
- 场景表复用配置表样式，长 ASCII 场景名可能在窄屏撑破页面；
- `@clear`、`@wait` 等实现术语直接暴露给普通用户；
- 场景只可阅读，无法沿现有 Editor 导航直接打开。
- 剧本存在编译错误时，统计计算可能抛出异常并让已清空的主区保持空白。

### 2.2 审计页

- 问题条目依赖彩色左竖线、卡片背景和位移悬浮；
- 可点击 `div` 只对鼠标友好，键盘没有明确的跳转控件；
- 原始问题代码、文件路径、JSON 形状和英文文件名压过了人的任务；
- “添加到名词表”动作夹在整条可点击区域内，焦点层级不清；
- 缺少页面标题、问题分组和明确处理顺序。
- 项目只有部分场景编译成功时，页面可能对局部结果显示“未发现问题”，形成全项目已检查的假象。

## 3. 设计选择

采用方案 A：统计与审计仍是两个独立模式，但使用同一份专属 `project-health-workspace.css` 和同一套连续页面层级。

不采用以下方案：

- 不合并成一个新模式，因为这会改变稳定导航合同并把两种不同任务混在一起；
- 不新增“项目健康分”、完成率、趋势或更新时间，因为现有数据没有这些事实；
- 不继续复用通用卡片、配置表和全局 `.issue`，因为它们正是当前视觉冲突来源。

## 4. 数据与行为边界

### 4.1 继续使用的真实数据

统计页继续只使用 `computeProjectStats()`：场景数、总字数、台词/旁白行、选择肢、结局、CG 解锁、预估时长和逐场景统计。不得推导进度、质量、完成率或排行榜。

审计页继续只使用 Core 的 `auditSpeakers()`、`auditTerminology()`、`AuditFinding` 和现有 `computeSpeakerPairs()`。不得在 Editor 复制第二套审计算法或改写问题严重度。

### 4.2 继续使用的写入与导航

- 统计场景跳转通过新增的本地 `bindStatsHooks()` 接到现有 `jumpToScene()`；
- 审计定位继续通过现有 `onJumpHook` 和 `jumpToScene()`；
- 名词变体写入继续通过现有 `onAddVariantHook` 路由到配置页；
- 不新增持久状态、文件格式或后台接口。

项目替换时必须先失效上一项目的待处理校验回包，并清空配置行缓存与撤销历史，避免旧 finding 或旧名词表被写入新项目。校验结果落地时，如果审计页正打开，只重绘该页，让 waiting/问题列表及时更新。

## 5. 统计页信息架构

顺序固定为：

1. 页面标题“项目概览”和一句用途说明；
2. 一个主要结论“预估通关时长”；
3. 连续的四组事实：内容规模、文本构成、互动结构、解锁内容；
4. “按场景查看”表格；
5. 默认收起的“计算说明”。

主要结论和次级事实使用留白、字号和分隔线建立层次，不给每个数字套卡片。场景名使用真实 button，点击后沿现有编辑器入口打开。表格具备 caption、列 scope 和窄屏滚动容器；场景名允许断词，不制造页面级横向溢出。

空项目不显示七个零值，而显示“还没有可统计的场景”，说明打开项目或新建场景后会自动汇总。

统计计算失败时不得抛出到主渲染链，而显示“暂时无法生成项目概览”，引导先修复剧本校验错误；原始异常只进入折叠技术信息。

## 6. 审计页信息架构

顺序固定为：

1. 页面标题“文字一致性检查”和用途说明；
2. 当前结论、说话人数、名词条目数和问题数量；
3. “建议处理”问题组；
4. “请确认”问题组；
5. 默认收起的名词表/技术说明。

每条问题使用连续记录行，不使用彩色单侧线。默认显示中文类型、人的问题描述和明确操作：

- `CONSIST_TYPO` → “疑似角色名笔误”；
- `CONSIST_HONORIFIC` → “称谓变体待确认”；
- `TERM_VARIANT` → “设定用词未统一”；
- 未识别代码 → “文字一致性问题”。

原始 code、文件路径和行号进入“查看技术信息”；有可定位场景时提供真实 button“打开场景 · 第 N 行”。称谓问题的变体写入按钮作为独立操作，不嵌套在可点击容器里。

未完成校验时仍渲染页面标题，再显示“正在等待项目校验”；没有发现项时显示明确空态。未配置名词表只说明“称谓检查可用，设定用词检查尚未启用”，文件路径和 JSON 形状放入折叠说明。

当 `lastValidation.issues` 仍包含 error 时，结论必须显示“检查不完整”。可以继续展示已成功编译场景中的发现，但不得把局部零发现描述为全项目通过；应明确提示先修复剩余剧本错误再确认全项目。

## 7. DOM 与样式

- `#stats-view` 与 `#audit-view` 分别设置 `data-editor-panel="stats|audit"`；
- 两页根内容使用 `.project-health-workspace`；
- 新建 `src/styles/project-health-workspace.css`，只使用现有 `--surdet-*` token；
- 从 `styles.css` 删除 Stats/Audit 专属旧规则，不改变 Script 工作区内已作用域的 `.issue`；
- 不使用彩色左线、渐变、玻璃、胶囊、阴影卡片墙、悬浮位移或 fixed/sticky 主操作；
- 选中、焦点和可点击性通过完整 outline、边框和背景表达。

## 8. 响应式与可达性

- 1024px 以下收紧摘要列数；
- 720px 以下摘要变为单列，表格保留自身横向滚动；
- 480px 以下标题和操作自然换行，页面无横向溢出；
- 表格有 caption 和 `scope="col"`；
- 场景跳转和审计跳转均使用真实 button；
- 技术详情使用原生 `details/summary`；
- 所有交互保留 `:focus-visible`，并尊重 `prefers-reduced-motion`。

## 9. 验证策略

先建立最小 RED，覆盖专属样式加载、稳定 panel 身份、无 KPI 卡片墙/彩色左线/浮空动作、表格窄屏保护、统计键盘跳转、坏剧本中文故障态、审计中文类型与独立操作、部分编译时的“不完整”提示、技术信息折叠。随后实现纯前端改动。

最终只运行一次 Pass 7 聚焦测试、一次 Editor 全量、一次 typecheck 和一次写入 D 盘的 build。实际浏览器检查 1440×900 和 390×844 两个尺寸的层级、键盘操作、无页面横向溢出；不建立新浏览器平台或证据包。

## 10. 完成条件

- 统计页不再是 KPI 卡片墙，空项目和逐场景阅读清楚；
- 审计页不再使用彩色单侧线或鼠标专用可点击 `div`；
- 用户默认看到中文任务，技术 code/path/JSON 默认折叠；
- 两页保持现有真实数据和写入边界；
- 项目切换不会把旧校验回包或名词表缓存带入新项目；
- 桌面与窄屏可读且无页面横向溢出；
- 聚焦、Editor 全量、typecheck/build、浏览器和 Luna 复核通过；
- 精确提交、普通 push 与同提交 CI 完成；
- 主线 Wave 7 未启动。
