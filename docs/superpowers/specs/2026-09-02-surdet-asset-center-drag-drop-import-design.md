# Surdet 素材中心拖放导入设计

## 1. 目标

补齐素材导入规格已经承诺、但当前 Editor 尚未实现的拖放入口：用户可以把普通文件直接拖到素材导入工作台，随后继续使用现有的中文分类、目标名称、冲突检查、显式确认、安全写入、回执和撤销流程。

这不是第二套导入系统。拖放只负责把浏览器提供的 `File` 对象交给现有 `AssetImportWorkspace.addFiles()` 路径；它不得绕过既有 authority，也不得直接写项目文件。

## 2. 阶段决定

本增量是素材中心 Phase 3 的收口项。完成后，Phase 3 可认定为具备大型项目所需的洞察、文件夹导航、真实缩略图和自然导入入口。

项目所有者希望拥有“引用感知的素材移动与重命名”，但该能力会同时触及物理文件、场景、时间轴、角色、字体和其他引用，必须独立设计写入 authority、冲突预览和失败恢复。因此它被明确保留为下一阶段，不得混入本轮。

## 3. 范围

### 3.1 包含

- 在现有“第一步 · 选择文件”区域接收普通文件拖放；
- 文件选择按钮继续保留，并与拖放共享同一 `onSelectFiles(files)` 入口；
- 支持一次拖入多个文件，数量继续受现有 512 个文件上限约束；
- 拖入前、可放下、不可放下和完成接收均使用简短中文状态；
- 已有草稿文件继续保留，合法拖放向当前草稿追加文件；
- 当导入操作已经锁定文件集合时，文件选择与拖放同时不可用；
- 键盘用户仍可使用原生文件选择控件完成同一任务；
- 800px 窄窗口保持可读，不产生页面级横向溢出。

### 3.2 不包含

- 文件夹递归导入；
- 网页链接、HTML、纯文本或剪贴板内容导入；
- 覆盖或替换既有素材；
- 移动、重命名、删除、转码或去重；
- 新增项目文件、sidecar、标签、收藏、缓存或第二套素材索引；
- 修改 Authoring、CLI、Agent Port、导入 authority 或项目格式；
- 启动引用感知移动/重命名、Frontend Pass 5 或 Wave 7。

## 4. 交互设计

现有文件选择区继续承担主入口，不新增大面积虚线框、浮层、彩色左竖线、渐变或独立卡片墙。文件选择标签扩展为一个克制的拖放表面：

- 默认文案：`选择文件，或拖到这里`；
- 文件拖入且可接受：`松开即可加入待导入列表`；
- 文件集合已锁定：`当前导入已开始，暂时不能加入文件`；
- 拖入内容没有普通文件：`这里只接受本机文件`；
- 文件接收后，焦点和后续编辑仍留在当前工作台，不自动提交。

可放下状态使用完整背景与边框变化，不使用单侧彩色竖线。颜色不是唯一语义；文案和 `data-drop-state` 同时表达状态。

## 5. 数据流

1. `dragenter` / `dragover` 只检查是否包含可接受的普通文件；
2. 可接受时阻止浏览器默认打开文件行为，并把表面状态设为 `ready`；
3. `drop` 提取 `DataTransferItem.getAsFile()` 返回的文件，排除目录项、空项和非文件项；
4. 合法文件数组交给现有 `hooks.onSelectFiles(files)`；
5. 现有 workspace 继续负责去重、预览 URL、类别建议、目标名称和文件上限；
6. 后续 plan、upload、commit、cancel、recovery 和 undo 完全沿用当前 authority 链路。

拖放层不保存文件、不创建 Object URL、不计算目标路径，也不判断导入是否可提交。

## 6. 状态与错误

- `filesLocked=true` 时不调用 `onSelectFiles`，也不改变当前草稿；
- 只有普通文件时才对 `dragover` 调用 `preventDefault()`，避免把网页链接误当文件导入；
- 离开拖放区域、完成 drop 或工作台重绘后，视觉状态回到 `idle`；
- 拖入目录或非文件内容时只在当前选择区显示中文说明，不弹全局错误、不清空已有草稿；
- `onSelectFiles` 后续的文件数量、重复和预览处理继续由既有 workspace 负责，本层不复制业务规则。

## 7. 可访问性

- 原生 `<input type="file" multiple>` 始终存在；
- 拖放表面不是唯一入口，也不伪装成额外按钮；
- 状态文字使用 `aria-live="polite"`，只播报状态变化；
- 文件集合锁定时，选择控件保持 `disabled`，拖放表面同时暴露不可用状态；
- 现有文件列表、分类、名称编辑和提交按钮语义不变。

## 8. 实现边界

- 修改 `packages/editor/src/panels/asset-import-workbench.ts`：纯文件提取 helper、拖放状态和事件绑定；
- 修改 `packages/editor/src/styles/asset-import.css`：克制的默认、ready、blocked 状态；
- 修改 `packages/editor/test/asset-import-workbench.test.ts`：永久行为与视觉合同；
- 必要时扩展现有 Asset Center 浏览器 runner，但不得创建第二个拖放 runner；
- 不修改后端与共享契约。

## 9. 验证

- 纯测试证明只提取普通文件，目录、链接和空项不会进入 `onSelectFiles`；
- UI 测试证明拖放与文件选择共用入口，锁定状态不会接收文件；
- 现有素材导入工作台聚焦测试保持通过；
- Editor typecheck 与 build 通过；
- 一次真实浏览器检查证明：多文件拖入后进入现有草稿、不会自动提交、锁定后拒绝追加、800px 无横向溢出；
- 不重复全仓库验证；普通推送后由单次远端 CI 承担全仓库回归。

## 10. 完成标准

1. 用户可以把多个普通文件拖入现有导入工作台；
2. 拖放和文件选择得到相同草稿结果；
3. 目录、链接、文本和锁定状态不会触发导入；
4. 拖放不会绕过冲突检查、确认、authority 或撤销链路；
5. 页面主要文案为自然中文，无新增 AI 风卡片、彩色竖线或悬浮操作；
6. 后端、项目格式和现有素材均未变化；
7. Phase 3 收口事实与下一阶段的引用感知移动/重命名方向写入现有长期台账。
