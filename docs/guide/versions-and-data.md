# 版本与数据支持

> 本页口径已由技术负责人按源码核对（#40 评论 6128340095），说明的是当前实现，不是对以后版本的兼容承诺。其中「剧本改动和旧存档」一节是源码核对结果，没有做专项验收。

作品里有三类数据会随引擎升级而变化：剧本、项目文件和玩家存档。

## 剧本（`.gal`）

- `.gal` 文件里没有版本号，总是按当前的 [DSL 规范](../dsl-spec.md) 解析。
- Editor 不会自动改写你的剧本，但剧本必须符合当前语法。这不是对任意历史写法的兼容承诺；不合当前语法的写法会出现在问题列表里。
- 已知的写法变化：注音只认 `<ruby=读音>字</ruby>`，不再兼容旧的 `世界《せかい》`。旧写法**不会报错**，而是按字面显示全部字符（书名号原样显示）。需要自己用查找搜「《」，逐处改成新写法。

## 项目文件

- 导出 Windows 游戏时，「Windows 版本」的默认值取自 `package.json` 里的 `version`。`game.config.json` 里也有一个 `version`，导出不读它。两者都是**作品**的版本号，和引擎版本无关。
- `package.json` 里的 `name` 是作品身份，决定玩家存档的位置。改标题或换导出文件夹都不会改变它；不要手动修改。
- 配置里各部分（例如译稿目录 `textCatalog`、作品界面 `ui`）有各自的结构版本号，由 Editor 读写，作者不需要手动改。

## 玩家存档

- 当前存档结构版本是 **3**（`packages/core/src/save/save-manager.ts` 中的 `SAVE_SCHEMA_VERSION`）。
- 合法的版本 1、2 存档，以及没有版本号的旧结构，会经现有迁移逐级升到版本 3（`packages/core/src/save/migrate.ts`），之后仍必须通过当前的结构和内容校验。**不是所有旧存档都保证能载入。**
- 版本号**高于**当前引擎支持的存档会被拒绝，提示「存档 schema 版本 X 高于引擎支持的 3」；缺少升级路径的存档也会被拒绝，不会强行读取。
- 用到项目插件的存档，读取前要先启用对应插件，否则提示 `PLUGIN_REQUIRED`。
- 文字记录随存档保存。没有文字记录字段的旧存档，读档后从空记录开始；重播当前这句会产生第一条新记录，不会带入读档前的记录。
- 已知限制：修复前生成的、正处于时间轴淡入或染色效果中途的旧存档会被明确拒绝，不猜测效果起点；旧式立绘转姿态时生成的缺字段快照也不会被放松校验强行接受。详见[当前限制](../known-limitations.md#旧版演出中途存档)。

## 剧本改动和旧存档

作者发布新版本后，玩家用旧存档继续玩：

- 存档所在的场景被改过时，引擎会报告「存档与剧本版本不一致」，但仍按存档里记下的指令位置尝试恢复；位置超出新剧本范围时，会收到场景里有效的范围内。
- 引擎**不会**按台词内容重新定位，所以恢复后可能落在另一条指令上，例如前后差几句。
- 共享 Player 目前只在开发者控制台里记一条警告，**玩家看不到提示**。
- 版本 1、2 的旧存档没有场景校验信息，不会报告这种不一致。
- 存档所在的场景，或调用栈里要返回的场景被删除时，读档会被拒绝。
- 变量、插件和演出状态的其他校验照常进行，不合格同样拒绝。

所以发布更新前，建议拿旧存档实际读一遍，尤其是改过、删过台词的场景。

## 设置

玩家设置（文字大小、减少动态效果等）按同一作品、同一台设备保存，和单个存档分开；读档不会改变设置。设置的保存格式以后是否变化，本页不作承诺。
