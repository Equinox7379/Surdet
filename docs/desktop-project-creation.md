# Windows Editor：新建项目接口

本页供桌面前端接入使用。项目生成复用 CLI 的 `createProject`，不修改 Player 或创作权限合同。后端接口、模板随包与 Windows 目录版在本阶段实现；首页创建表单由前端接入，不能把仅有接口说成完整界面已经交付。

## 前端只调用这两个方法

接口位于 `window.surdetDesktop`，类型见 `packages/editor/desktop/contracts.ts`。只有真实桌面主页面提供桥；浏览器开发页和试玩子页面没有此能力。

### `chooseProjectLocation(): Promise<{ id: string; location: string } | null>`

- 打开原生“选择新项目的保存位置”目录对话框。选的是父目录，项目会创建为其下的一个新文件夹。
- 返回 `location` 仅用于显示；提交创建时只使用 `id`，不能向后端传入任意目标路径。
- 用户取消或另一个目录选择正在进行时返回 `null`，不创建文件，前端保留原选择即可。
- 一次新的成功选择使本窗口之前的位置编号失效；编号不跨窗口、重启或持久化复用。

### `createProject({ locationId, name, template }): Promise<void>`

三个字段均为必填，不能追加 `directory`、`path`、`templatesRoot` 等字段。

| 字段 | 语义 |
| --- | --- |
| `locationId` | 本窗口通过原生选择取得的当前编号 |
| `name` | 作品标题兼新文件夹名，去除首尾空白后长度1至120（按JavaScript字符串长度，前端可用maxlength=120）；可用中文、日文和空格，但不能用Windows保留名、路径分隔符或非法文件名字符，不能以点结尾 |
| `template` | `blank` 空白项目；`example` 现有港口示例。使用既有模板，不重新生成美术 |

成功时项目完整写入新目录，并沿现有桌面流程打开项目窗口、记入最近项目。启动页可能随之关闭；当前已打开的其他作品窗口不会被替换。前端不应再调用 `openProject()` 弹第二次选择框，也不用在成功后读取返回的路径。

创建过程中禁用重复提交。错误以Promise拒绝返回，原生桥异常可能带Electron调用前缀；界面应给出简洁中文错误，不将协议前缀当作正文。常见情况：尚未选择位置、编号过期、名称不合法、目录已存在、位置被替换/不可写、模板文件不可用。已有目录一律拒绝，不提供覆盖选项。

生成失败会清理本次未发布的暂存目录，不删除已有作品。若完整项目已经生成、后续打开窗口失败，会明确提示“项目已创建在…但暂时无法打开”；这个完整目录保留，不能提示“什么都没发生”或自动再创建一遍。成功创建后位置编号失效；需要再创建另一个项目时重新选择位置。

## 数据与授权边界

- 新目录中的 `game.config.json.title` 使用作品名；`package.json.name` 由后端生成独立稳定身份，前端不生成或修改它，改标题也不应改变保存身份。
- 新作品是独立目录，不注册到引擎仓库的workspaces；创建只写所选父目录下的新子目录，不修改已打开作品。
- `.mcp.json.example` 和 `AGENTS.md` 随新作品提供。示例不自动启用MCP，也不授予Agent来源写回权限。
- 名称/模板/编号在主进程验证；主进程沿既有可信主帧检查，renderer不能指定模板来源或任意写入位置。
- 本阶段不实现浏览器端创建、导出发行、安装依赖、自动改Player样式或新的模型平台。

## 桌面构建与模板

`desktop:build` 将CLI模板复制至开发产物的 `desktop-dist/templates`，并保留CLI模板许可说明。Windows打包把它们放在应用资源目录的 `templates` 中、ASAR之外；开发与打包各从明确的位置读取，不查找源码仓库作为备用路径。

项目在Editor内编辑、保存、试玩不需要为新项目运行npm安装。若外部Agent或作者要独立使用CLI/MCP及Web构建，仍按项目README与AGENTS准备对应工具；不能把桌面内置运行时冒充已在系统安装了所有CLI包。

当前模板中的故事、美术及依赖仍按原许可分别处理，参见CLI NOTICE及仓库第三方说明。本轮目录版用于本机验收，不等于公开发布或授权再分发示例素材。
