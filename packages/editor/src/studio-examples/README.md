# Editor 工作台布局示例

2026-09-15 Owner 授权同步制作几个示例，并明确“最高原则是不得丢弃我们已经有的后端”。方向参考 LetsGal Studio 的桌面创作工作台；该程序的代码、图片和品牌资产没有用于本示例。

启动现有 Editor 开发服务后，访问 `/studio-examples.html`。顶部直接切换三个布局，切换时沿用同一份副本和同一个运行器：

- A 标准工作台：目录、可读剧本块、预览与属性同时展示。**Owner 于本轮明确“我选 A”，作为后续正式 Editor 重做的布局基线；当前配色、组件外观与交互细节仍可完善。**
- B 连续写作：收起目录，弱化演出块，扩大连续正文。
- C 演出工作台：舞台占据主区域，下方为横向片段，右侧为属性。

可操作：切换片段，编辑对白、背景、立绘表情/位置和等待时长，修改源码，撤销，检查语法，真实试玩、选择和定位运行行，保存及重开浏览器内的示例副本。素材与流程页展示实际示例数据。

## A 的后续设计标准

Owner 随后关注抄袭风险，并希望 Surdet 比参照产品更完善。A 确定的是工作区组织方式，最终视觉、图标、组件和交互由 Surdet 独立设计；不临摹参照产品的整套页面，也不以简单换色当作独立设计。

完善程度用实际创作流程衡量：剧本、流程、时间轴和预览保持同一对象上下文；明确正在编辑和试玩的版本；把已有 Agent 修改、差异比较、审阅和写回接入同一工作台；补齐可调整面板、长篇编辑、键盘操作和可靠保存。它们是正式迁移的设计要求，不是本示例已经完成的能力，也不据此宣称已全面超越其他产品。已有后端与项目数据始终保留。

## 已有系统如何保留

| 本示例实际复用 | 原模块 |
| --- | --- |
| 剧本文档解析、行结束符与序列化 | `../model.ts` → `@surdet/authoring` |
| 语法编译 | `@surdet/core` 的 `compileScene` |
| 试玩、选择、画面与运行轨迹 | 现有 `preview.html` / `../preview.ts` |
| 可用工作面清单 | `../shell/editor-modes.ts` |
| 素材 | 仓库《零点之后》的既有图片，仅引用 |

没有修改 Core、Authoring、CLI、Renderer、项目格式、公共接口、正式 Editor 入口、项目保存与恢复、Agent 入口、候选组合、审阅、批准或写回逻辑。没有创建第二套运行器。所有新界面状态只用于布局示例。

## 明确的边界

- 三个片段是独立示例副本，部分对白摘自《零点之后》，并不构成该游戏的完整接入。
- “保存示例副本”只写浏览器 `localStorage` 的专用键 `surdet.editor-layout-examples.v1`，不接触文件系统或项目写服务。浏览器禁用存储时会明确失败。
- 不发布正式观察，不产生候选，不批准、不写回。原有能力说明提供了通往现有 Editor 的入口；没有把这些业务虚构为已经完成新 UI 接线。
- 选中一行调整属性和实际播放到一行是两个独立位置。修改后旧预览被遮挡，重新试玩从片段开头运行；本示例没有实现任意源码位置的状态推断。
- 试玩仍是现有 Editor 的轻量预览，不能代替完整 Player 系统验收。

示例随开发服务可用。单独检查含示例的构建：`npm run build -w surdet-editor -- --mode studio-examples`；正常 Editor 构建不包含示例入口或示例图片。
